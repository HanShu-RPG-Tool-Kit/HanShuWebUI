# 汉书 .hs 语法说明（给作者 & Agent）

本文约定剧本文件（`.hs`）的正式语法。**写出的内容必须能通过这些规则**；不确定时宁可少写，不要发明语法。

---

## 1. 角色对白块

### 规则
- 角色名：仅 `[A-Za-z_][A-Za-z0-9_]*`（字母/数字/下划线，不能以数字开头）
- 多行：`name:` 独占开头，正文若干行，**单独一行** `//` 结束
- 单行：`name:正文//`
- 选项行**不能**出现在对白块内部

### 正例
```hs
narrator:
夜色压在城墙上。
卫兵的脚步由远及近。
//

guard_a:站住！//
```

### 反例
```hs
# 错误：中文角色名
卫兵:
站住！
//

# 错误：用全角冒号
narrator：夜色很深。//

# 错误：对白块里塞选项
narrator:
你要离开吗？
-是的:那就走吧//
//
```

## 2. 选项树（仅在对白块外）

### 规则
- 必须从**行首**开始写 `-` / `--` / `---`…（层数 = `-` 个数）
- 行内若要字面量 `-`，写成 `\-`
- 常见形态：
  - `-选项文案:回复正文//`
  - `-选项文案:>>inject_name//`（跳到注入点 `@inject_name`，见下节）
  - `-选项文案:<<回复正文//`（说完后回到上一级选项重选，见下节）
  - `---只有选项文案//`（无回复）
- `:` 右侧判定（按优先级）：
  1. 以 `<<` 开头 → 回退重选（其后为可本地化回复）
  2. 以 `>>` + 标识符 → 跳转到对应 `@` 注入点
  3. 否则 → 普通回复正文

### 选项树边界
一棵选项树 = 从某个顶层 `-` 起，到被**打断**为止的连续选项行（含 `--` / `---`… 子级）。

**打断**（结束当前树）：
- 对白行（`speaker:`）
- `@` 注入点 / `@@` 终止符
- 空行
- 独立行为信号行（`!id …`，见信号节）

**不打断**：
- `#` 注释
- 选项前置附件：`?` / `!:` / `:!`（必须紧贴其所约束的选项行）

### 正例
```hs
-这是哪:大牢……//
--我当然知道这里是大牢:那就别乱跑。//
---该死的哑巴//
-我为什么在这:有人说你是魔女。//
-去问卫兵:>>guard_question//
-魔女？我怎么可能是魔女？:<<那……那到底是怎么回事呢？//
```

### 反例
```hs
# 错误：行首有空格
 -这是哪:大牢//

# 错误：把选项写成 speaker
-这是哪:
大牢
//

# 错误：未转义的行内 -
旁白:他打出一记-重拳。//
# 应写作：
旁白写法错误示范请改用 narrator:他打出一记\-重拳。//
```

## 3. 信号（行首，仅行首生效）

剧本只**约定如何发/问信号**；具体求值、执行、返回值由**外部驱动器**决定。  
形态一律：前缀 + `id` + 可选参数。`id`：`[A-Za-z_][A-Za-z0-9_.]*`。  
参数：空白分词；含空格用 `"hello world"`；引号内 `\"` 转义。`.hs` **不解释**参数语义。

| 写法 | 角色 |
|------|------|
| `?id args...` | **条件信号**：约束**下一选项行**是否可见（驱动器须给出真假） |
| `!id args...` | **行为信号**：独立可执行语句（与对白行同级；**打断**选项树） |
| `!:id args...` | **选项行为信号**：约束下一选项行的「选项」侧 |
| `:!id args...` | **答复行为信号**：约束下一选项行的「答复」侧 |

### 选项前置附件（紧贴选项，中间不能有空行）

合法排列（各段至多一行，可省略后几段，但顺序固定）：

```text
[?]
[!:]
[:!]
-选项行…
```

规则：
- 一个选项最多一个 `?`，且 `?` 必须在 `!:` / `:!` **前面**
- 若同时要 `!:` 与 `:!`，必须先 `!:` 再 `:!`，**不能颠倒**
- `?` / `!:` / `:!` 与选项行之间、彼此之间**不能有空行**
- `!:` / `:!` **不打断**选项树；独立 `!` **会打断**

### 正例
```hs
?visible task=prologue
!:on_pick start_quest
:!on_reply "hello world"
-硬闯:你力气够大。//

!start_quest prologue

guard_a:站住！//
```

### 反例
```hs
# 错误：? 与选项之间空行
?visible task=prologue

-硬闯:你力气够大。//

# 错误：顺序颠倒
:!on_reply
!:on_pick
-硬闯:走。//

# 错误：缩进（仅行首）
 ?visible
```

## 4. 回退 `<<`（重做上一级选择）

### 规则
- 写在选项的 `:<<` 之后：`-文案:<<回复正文//`
- 引擎播完回复后，**退回上一级选项菜单**并重新展示可选分支（顶层 `-` 则重开当前这组选项）
- `<<` 后的正文是普通对白，会进入本地化映射；可为空：`-文案:<<//`
- 与 `>>`（跳转）不同：这是回退，不是前进
- 文本里要写字面量 `<<` 时用 `\<<`

### 正例
```hs
-我只是个普通女孩。:<<真的吗？//
--真的。:>>rat_question_conversion_2//
--逗你的。:<<啊！！！！！！！！你别靠近我！//
```

### 反例
```hs
# 错误：写成跳转却想回退
-回去:>>parent//
```

---

## 5. 跳转 `>>name`（到注入点）

### 规则
- 写在选项的 `:>>` 之后：`-文案:>>name//`
- `name`：`[A-Za-z_][A-Za-z0-9_]*`，对应剧本中的注入点 `@name`
- 与回退 `<<` 对称：前进用 `>>`，回退用 `<<`
- 不是可本地化答复；本地化映射不收录 `>>name` 本身
- 文本里要写字面量 `>>` 时用 `\>>`

### 正例
```hs
@guard_question
guard_a:……//
-离开:好。//

@later
narrator:后来……//

-回去问卫兵:>>guard_question//
```

### 反例
```hs
# 错误：旧写法单个 >
-回去:>guard_question//

# 错误：带 @ 或空格
-回去:>>@guard_question//
-回去:>> guard_question//
```

## 6. 注入点 `@后缀`

### 规则
- **单个** `@` + 非空白后缀，不跨行（如 `@dialog`、`@guard_question`）
- 用作引擎注入点；可被选项 `:>>name` 跳转定位
- **不要**与行首终止符 `@@` 混淆
- 不要随手编造无约定的 `@` 标记

### 正例
```hs
@dialog
```

### 反例
```hs
# 错误：中间有空格 / 跨行
@ dialog
@dia
log
```

---

## 7. 终止符 `@@`

### 规则
- **行首**写 `@@`（可带后缀，如 `@@` / `@@end`），整行视为**终止符**
- 表示当前剧本段结束
- **不是**注入点：注入点是单个 `@`（如 `@dialog`）；终止符是行首 `@@`
- 不要缩进；不要写在对白块内部

### 正例
```hs
@guard_question
guard_a:……//
-离开:好。//
@@
```

### 反例
```hs
# 错误：行首有空格
 @@
# 错误：单 @ 是注入点，不是终止符
@end
```

## 8. 注释

### 规则
- `#` 行注释，其中 `#` 应位于行首，非行首的 `#` 将被认为是字面量
- `#【场景】` / `#【动作】` 为带标签注释（可整行）

### 正例
```hs
# 这一段先保留
#【场景】黄昏，青石巷。
#【动作】撑伞，停步
```

## 9. i18n 本地化文本与键名

### 规则
- **可本地化文本**：对白块正文、选项文案、选项回复；`#` 注释、信号行、`>>name`、`<<`、`@@`，以及 `#stopparse` 之后的全部文本都不是
- **键名**：8 位小写十六进制（`0-9a-f`），例如 `7f3a91c2`。正文里出现的键名就是可本地化文本的占位
- **键是文本哈希**：自动成键时由**该段文本**算出（同一段文本永远得到同一个键）；万一撞车，按固定次序二次哈希、三次哈希……直到不冲突。所以「逆解析 → 再解析」会拿回同一个键，已有译文不会丢
- **映射文件**：语言文本是**工程资产**，路径由源文件推导：`assets/<语言标签>/lang_<源后缀>/<文件名>.lang`（JSON 对象，键名 → 文本）。例如 `hanshu/cp1.hs` ↔ `assets/zh_cn/lang_hs/cp1.lang`；配音在 `assets/<语言标签>/voice_<源后缀>/<文件名>/<键名>.ogg`
- **引用资产（`.ref`）**：同一个对等位置上也可以放一个 `.ref` 文本文件（正文是一行包内路径，指向另一份音频资产）—— 这是「引用资产」这种配音方式，省掉一份音频拷贝。`.ogg` 与 `.ref` 同时在时 **`.ogg` 优先**；引用**只认一层**（不能指向另一个 `.ref`），目标必须是**本包内**的音频。导出 PAK 时引用会被**落地成对等位置上的 `.ogg`**（引擎只认 ogg，PAK 里不会出现 `.ref`）
- **语言标签**：小写下划线形式，如 `zh_cn`、`en_us`、`ja_jp`；一个语言一个文件。**规范标签是「语言_地区」**，不要写 `en`、`ja` 这种裸语言码；agent 写译文前应先 `list_locales`，**沿用工程里已有的标签**（工程里是 `en_us` 就写 `en_us`）
- **`#stopparse` 指令**：顶格一行；从这一行（含）起，编辑器**不再解析成键**，之后正文原样保留、不参与本地化。适合"这段先不翻译"或需要引擎处理的原文片段
- 值里保留真实换行（一个多行对白块就是「一个键、值里多行」）；正文里的 `\-`、`\>>`、`\<<` 等转义在写入映射时还原成字符本身
- 渲染是**渲染级替换**：文档里始终是键名，编辑器按当前语言把映射文本画在键名的位置上，文档本身不会被改写；映射缺失时显示键名（红底）
- 编辑器里按住 `Ctrl` 显示原始键名（蓝色虚线框），不按时命中显示黄底、缺失显示红底；点击框可等位置编辑——按住 `Ctrl` 改键名，否则改映射值

### 人类作者
正常写文本即可：在语句末尾敲下 `//` 的那一刻，编辑器会**自动生成键名并把原文写入 i18n 映射**——正文被换成键名，文本进入 `<文件名>.lang` 资产。作者不需要手写键名，之后按语言分别编辑映射。
需要**保留原文、不参与本地化**的段落（比如引擎要读的原文），在它前面顶格写一行 `#stopparse` 即可：这一行往后的正文都不会再被自动成键。

### Agent 作者
自动成键可能在任何可能时候发生，对Agent是不稳定的。Agent 应当遵循以下工作流程：

1. **关闭成键解析**，使用 `#stopparse` 指令禁止自动成键，以保证正常编辑文本；
2. **逆解析**，选择一个基准语言，用 `unparse_hs(source, locale)` 将文本还原到基准语言；
3. 正常编写文本；
4. **主动解析成键**，删除 `#stopparse` 指令，主动使用 `parse_hs(source, locale)` 走一次解析（自动成键，键由文本哈希得到）
5. 再**单独修改 lang 映射**，为这些键补齐目标语言文本：键与文本一一对应，不遗漏、也不多余。

**警告**: 不要手写十六进制键名，使用关闭解析来编辑自然语言文本，而后主动解析来成键！

### 正例

`cp1.hs`：
```hs
narrator:7f3a91c2//

-0b41d5ee:a7c3e812//
--c1d2e3f4//
```

对应的本地化文本：
```json
{
  "7f3a91c2": "夜色压在城墙上。\n某个犯人醒来了。",
  "0b41d5ee": "这是哪？",
  "a7c3e812": "大牢……",
  "c1d2e3f4": "该死的哑巴。"
}
```

### 反例
```hs
# 错误：正文里还是原文，没有换成键名
narrator:
夜色压在城墙上。
某个犯人醒来了。
//

# 错误：使用多行键，但多行键会被识别为文本
narrator:
faw613da
7f3a91c2
//

# 错误：键名不合规（位数/字符不符合 8 位小写十六进制）
narrator:7F3A91C//

# 错误：键名写对了，但 lang 映射里没有这个键（渲染为红底「缺失」）
guard_a:deadbeef//
```

## 10. Agent 改稿自检清单

写入前请确认：
1. 所有 speaker 名是否只含字母数字下划线？
2. 每个对白块是否都有结尾 `//`？
3. 选项是否都在块外、且从行首开始？
4. `:>>name` 跳转是否对应已有 `@name`？
5. `:<<` 是否用于「说完回退重选」，且其后文案需要本地化？
6. 信号是否仅行首？选项前置是否为 `?` → `!:` → `:!` → 选项、且无空行？
7. 终止符是否行首 `@@`（不要写成单 `@`）？
8. 是否误把选项/中文当成 speaker？
9. 可本地化文本是否都进行了解析键名，并在 `<文件名>.lang` 资产（`assets/<语言标签>/lang_<源后缀>/`）里补齐了对应文本？
10. 需要**原样保留、不参与本地化**的段落，是否已在它前面顶格写一行 `#stopparse`？
