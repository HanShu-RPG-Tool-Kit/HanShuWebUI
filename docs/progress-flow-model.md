# 进度流程模型说明

本文描述 HanShu 进度流程工作区**当前**的画布模型与信号运行时（以 `src/workspaces/progress/model.ts`、`signals.ts` 为准）。集线器 / 网关 / 合取·析取逻辑节点已移除。画布操作用法见 [progress-workspace.md](./progress-workspace.md)。

## 1. 模型定位

| 层 | 职责 |
|----|------|
| **作者图** | 节点 + 类型化端口连线；文档 `hanshu.progress-tree` v1 |
| **运行时** | 信号沿导线传播；checkpoint / Goal / Predicate 的状态机 |
| **校验** | 端口基数、引用完整性；画布连线成环仅 **warning** |

Checkpoint **之间不能直连**，推进必须经「变迁」类节点。起点（entry）不是 checkpoint，只作为信号源与第一跳出口。合取 / 析取不再是独立节点；「多 Goal 同时成立」由**线性变迁的多 Goal 口**表达，「多路径汇合」由**合并变迁**表达。

`logic.links` 仍是画布连线存储（Goal / Predicate / 各类变迁），与 checkpoint 的 `children` 分支字段分开；旧草稿里的 `logic.nodes`（∧/∨）在解析时被剥离。

## 2. 节点一览

### 2.1 状态节点

| 节点 | 文档键 | 状态 | 角色 |
|------|--------|------|------|
| **Checkpoint** | `nodes` | 未激活 → 活跃中 → 已激活；或 → 已取消 | 阶段落点；入点收 **S**，出点可发 **A** |
| **Goal** | `goals` | 未激活 → 订阅中 → 已关闭 | 可人工完成的目标；订阅中发 **G** / **G-Y** / **G-N** |
| **Predicate** | `predicates` | 同 Goal | 条件谓词；订阅中发 **P** |

Goal / Predicate 的 `kind`（人工、计数、信号、等待阶段、外部）是**设计意图字段**，当前模拟器不解释具体条件，只模拟订阅 / 完成 / 关闭。

### 2.2 变迁与结构节点

| 节点 | 文档键 | 端口拓扑（入 → 出） |
|------|--------|---------------------|
| **线性变迁** | `transitions` | Goal（多，合取）+ Parent（1）→ Next（1） |
| **条件变迁** | `conditionals` | Predicate（1）+ Parent（1）→ Next（1） |
| **差分变迁** | `diffs` | Goal（1）+ Parent（1）→ 成功 / 失败（各 1） |
| **合并变迁** | `merges` | A 入（多）→ Next（1） |
| **交换变迁** | `swaps` | 每槽 inN（1）↔ outN（1）；末槽用尽自动扩容 |
| **起点** | `entry` | 无入；出 ≡ Next，只接一条 checkpoint |

## 3. 信号与状态

### 3.1 信号表

| 记号 | 种类 | 典型含义 |
|------|------|----------|
| **S** | `ckpt-transition` | 携带「原状态 → 新状态」，仅当与 ckpt 当前信念一致才接受 |
| **A** | `activation` | 激活 / 订阅（变迁 → Goal·Predicate；ckpt 出点 → 下游） |
| **G** | `goal-complete` | Goal 完成（线性合取） |
| **G-Y / G-N** | `goal-yes` / `goal-no` | 差分成功 / 失败 |
| **P** | `predicate-complete` | 谓词成立 |
| **D** | `cancel` | 关闭 Goal / Predicate |
| **C / C-R** | `query` / `query-response` | 「是否已关闭/已激活」询问与回报 |
| **S-C** | `cancel-cascade` | 取消级联（回灌上游） |
| **G-C** | `goal-cancel-cascade` | 活跃 ckpt 被取消后，通知变迁关掉 Goal/Predicate |

### 3.2 Checkpoint 与 S-C

- 进入 **已激活**：从 S **入点**发出 **S-C**（并可由出点发 **A**）。
- **入点**收 S-C：不转发；若当前为活跃中 → 已取消，并发 **G-C**；未激活则只吞掉。
- **出点**回灌 S-C：活跃中 → 已取消 + G-C；**未激活只转发、不改自身状态**。

### 3.3 变迁语义摘要

**线性变迁**

1. Parent 收 **A** → Next 发 S(未激活→活跃中)，向全部 Goal 发 **A**；无 Goal 则直接再发 S(活跃中→已激活)。
2. 某 Goal 发 **G** → 对该 Goal 回 **D**，向全部 Goal 发 **C**；均已关闭并回报 **C-R** 后 Next 发 S(活跃中→已激活)。
3. Next 回灌 S-C → Parent；回灌 G-C → 全部 Goal 发 **D**。

**条件变迁**（同线性，但单 Predicate）

1. Parent **A** → Next S(未激活→活跃中) + Predicate **A**；无谓词则直接完成。
2. **P** → 对该谓词 **D**，Next S(活跃中→已激活)。
3. S-C / G-C 转发规则同线性（G-C → Predicate **D**）。

**差分变迁**

1. Parent **A** → 成功口 S(未激活→活跃中) + Goal **A**。
2. **G-Y** → 成功口 S(活跃中→已激活)。
3. **G-N** → 成功口 **S-C**，失败口 S(未激活→已激活)。
4. 成功/失败口回灌 S-C → Parent + Goal **D**。

**合并变迁**

1. 任一条入线 **A** → Next S(未激活→活跃中)，并向全部入线上游发 **C**。
2. 全部回报 **C-R**（上游须为已激活 ckpt）→ Next S(活跃中→已激活)。
3. Next 回灌 S-C → 全部 A 来源。

**交换变迁**

1. 某槽收 **A** → 同槽 out 发 S(未激活→已激活)；其余槽 **入点**发 **S-C**。
2. 某 out 回灌 S-C → 同槽入点回灌。

**起点**：Ctrl 触发发出 S(未激活→已激活) 到唯一出口。

## 4. 结构约束

- Checkpoint 禁止直连；入口 / Parent / Next / 差分双出 / 交换槽等多处为**单线替换**。
- Goal / Predicate 出口单线；线性 Goal 口允许多线合取；条件 Predicate 口与差分 Goal 口均为单线。
- 画布有向边 = `entry.target` + `logic.links`。成环只警告，不阻断编辑（弹窗 + 校验栏）。

## 5. 表达能力分析

下面从「能写什么进度故事」看表达力。合取 / 析取**不再**作为可组合的布尔子图；逻辑被收进具体变迁的端口语义。

### 5.1 已具备的组合能力

| 模式 | 如何表达 | 说明 |
|------|----------|------|
| **顺序推进** | ckpt → 线性/条件 → ckpt | 基本流水线 |
| **多目标同时成立** | 线性变迁多 Goal + G 合取（C/C-R） | 「几件事都做完才过」；替代原 ∧ 节点在 Goal 侧的职责 |
| **谓词门闩** | 条件变迁 + Predicate | 「条件成立才过」；单谓词，不与 Goal 合取混在同一变迁 |
| **成败分叉** | 差分变迁 | 同一父阶段拆成功/失败后继 |
| **多路汇合** | 合并变迁 | 「几条线都已激活才继续」；替代原 ∧ 在路径侧的职责 |
| **互斥切换** | 交换变迁 | 选中一路完成，其余路上游被 S-C；近似「选一路」而非纯 OR 保留 |
| **并行扇出** | 已激活 ckpt 多出线发 A；或交换后多下游 | 结构上可并行；需作者自行控汇合 |
| **取消传播** | S-C / G-C / D | 活跃路径可被上游取消并关掉目标 |
| **空合取/空谓词** | 无 Goal / 无 Predicate 的线性或条件 | Parent A 后直接完成，便于占位 |

### 5.2 相对常见流程形式的覆盖

- **线性任务链**：强覆盖。
- **AND（合取）**：两种粒度——线性 Goal 合取（按已关闭）与合并变迁（按已激活）。**没有**通用布尔 ∧ 节点，不能对任意信号子树做嵌套合取。
- **OR（析取）**：交换近似「选一路并取消其它」。**没有**「任一完成即可、其它仍保留」的专用 OR 变迁，也没有 ∨ 节点。
- **条件分支（if/else）**：差分用 G-Y/G-N；条件变迁只表达「过/不过」的门闩，不自带假分支（假可接差分失败口或另起图）。
- **循环 / 重试**：画布允许环（仅警告）。运行时 S 带原状态匹配，环上重入是否安全取决于作者是否重置状态；**没有**内建「重试次数 / 回到活跃中」原语。
- **子流程 / 调用**：无嵌套流程节点；只能扁平拼图或靠外部 `kind`/资源引用描述意图。
- **时间 / 计数 / 外部事件**：Goal·Predicate 的 `kind` 可记述，**当前信号模拟不执行**这些谓词。
- **任意布尔组合**：已移除 ∧/∨ 节点后，不能再搭「(G1∨G2)∧P」这类作者侧布尔图；复杂条件需拆成多个变迁 / 多阶段，或留到引擎解释 `kind`。

### 5.3 理论视角（直观）

把 checkpoint 看作「令牌位」、变迁看作「受控跃迁」：

- 有 **同步**（线性 Goal 合取、合并 C-R）、**选择**（交换、差分）、**抑制**（S-C 取消）。
- 比简单状态机多了「外部完成源」（Goal/Predicate）与「查询确认」（C/C-R）。
- 比完整 Petri 网少：无任意权重、无抑制弧专用语法、无层次网；亦无独立逻辑门节点。
- 画布 DAG 非强制 → 可表达环，但语义需作者自洽。

### 5.4 表达力边界（缺口）

1. **无通用布尔组合子**：合取/析取节点已删除；AND/OR 只能落在变迁固定语义上，不能嵌套组合任意子式。
2. **无专用 OR 汇合**：难以干净表达「多线任一即可、且不取消其它」。
3. **无内建重试/复位**：已取消 / 已激活如何回到可再玩状态，无标准算子。
4. **无层级封装**：大图只能平铺，复用靠复制。
5. **条件解释层缺失**：模拟器假设人（或外部）在正确时机点 G/P/G-Y/G-N，真实引擎还需接计数、信号、外部 API。
6. **扇出无自动配对**：ckpt 多出口并行后，必须显式合并或交换，否则多令牌语义靠约定。

### 5.5 小结

当前模型适合描述：**阶段图 + 目标/谓词门闩 + 成败分叉 + 多路汇合/互斥切换 + 取消级联** 的叙事/任务进度。  
逻辑组合被**专门化进变迁**（线性合取 Goal、合并汇合、交换互斥、差分成败），表达更干净，但失去可任意嵌套的布尔子图。对 **BPMN 级工作流**、**强类型条件引擎**、**子流程库** 仍偏薄；作者侧拓扑与信号核已能支撑上述主路径的可运行草稿，并可用成环警告约束「尽量 DAG」的设计习惯。
