# 礼包：超参数与修饰器

同一份礼包常常要按条件给出不同的奖励，比如难度越高给得越多、队伍人数越多给得越多。汉书用两个概念来描述这种变化：

- **超参数**：由礼包作者与后端引擎约定的量（例如 `intensity` 奖励强度、`difficulty` 难度）。领取时由引擎注入，礼包里只写声明和默认值。
- **修饰器**：一个标量一元函数 `f(x)`。输入是条目字段的原值，输出是最终值，函数内部可以读取超参数。

```text
条目原值 rawdata ──► 修饰器 f(x) ──► 取整 / 下限 ──► 最终值
                       ▲
             超参数（引擎注入，缺省用默认值）
```

超参数卡和修饰器卡位于可编辑表单的最下方，上下排列。标题下方可填写 **标签**（`tags`）：给礼包打上游戏可查询的分类，交互与皮肤管理器类似（chip、回车添加）；建议用稳定标识如 `daily`、`event/summer`。

## 1. 声明超参数

在 **超参数** 卡片中添加一行：

| 列 | 说明 |
| --- | --- |
| 标识符 | 必填，手动输入。为空时该行**被无视** |
| 类型 | `float` / `int` / `bool` / `string`；`string` 不能参与表达式运算 |
| 默认值 | 必填；引擎未注入时使用 |
| 预览值 | 只在编辑器里生效，用来模拟引擎注入，不写入文件 |

新建礼包默认带四个超参数，它们的语义由引擎约定，可以按需删改：

| 标识符 | 类型 | 默认 | 语义 |
| --- | --- | --- | --- |
| `intensity` | float | 1 | 奖励强度 |
| `difficulty` | int | 0 | 难度 |
| `distributionCount` | int | 1 | 本次礼包由几个人分配；一次 `grant` 多名玩家时引擎默认可注入为人数 |
| `distributionId` | int | 0 | 当前玩家在本次分配中的序号，从 0 开始，取值 `0 … distributionCount-1`；多人一次 `grant` 时引擎默认可按列表下标注入 |

## 2. 编写修饰器

在 **修饰器** 卡片中添加。每个修饰器占一行，依次是 `标识符 (x) = 表达式  名称`。其中标识符必填，名称可选。表达式中：

- `x` 代表输入的原值；
- 直接写超参数名，例如 `intensity`；
- 可以调用其它修饰器，例如 `loot(x)`；
- 可以使用内置函数 `min max abs floor ceil round clamp step select lerp spline`。

行尾的圆点表示状态：绿色正常，红色有错误，灰色被无视。点击行尾箭头，或者编辑这一行时，会在行下方展开预览，显示错误信息，或者画出 `x` 从 0 到上限的曲线并列出采样值。

常用写法：

```text
x * intensity                               按强度线性放大
x * (1 + 0.25 * difficulty)                 每级难度 +25%
select(difficulty, 1, x, 3, x * 2, x * 3)   难度 0 原样，1–2 翻倍，3 及以上三倍
step(intensity, 2, x, x * 2)                强度达到 2 后翻倍
x * lerp(intensity, 0, 0.5, 1, 1, 3, 2)     强度 0→0.5 倍，1→1 倍，3→2 倍
clamp(loot(x), 1, 64)                       在另一个修饰器的基础上限制范围
```

多人分配时（一次 `grant` 传入多名玩家，或调用方自填分配超参数），`x` 是整份礼包的总量，修饰器按该玩家的 `distributionId` 算出该拿的那一份：

```text
floor(x / distributionCount)                                          平分，余数丢弃
floor(x / distributionCount) + step(distributionId, x - floor(x / distributionCount) * distributionCount, 1, 0)
                                                                      平分，余数依次补给前几号玩家
step(distributionId, 1, x, 0)                                         只有 0 号玩家拿
```

以 `x = 10`、3 人分配为例，第二种写法给 0、1、2 号的分别是 4、3、3。

完整语法和函数定义见 [表达式标准 V1](#kit-expr)。

## 3. 绑定到条目

可以绑定修饰器的字段，右侧都有一个小小的 **ƒ**：

| 位置 | 字段 |
| --- | --- |
| 物品（含随机池里的物品；可内嵌 ItemStack，或 `item` 链接物品库 `.item` 文件名，见 [物品库](#item-guide)） | 数量 |
| 药水效果 | 等级、时长 |
| 经验（标题栏） | 数量 |
| 随机池 | 抽取次数、分组权重 |

点 **ƒ** 选择修饰器。绑定后，ƒ 会显示修饰器 id 和按当前预览值算出的最终值：

- 蓝色：正常，悬停可看到 `loot(5) → 8` 这样的明细；
- 黄色：绑定的修饰器不存在或被无视，按原值处理；
- 红色：求值出错（例如除零），按原值处理。

所有可绑定字段都是整数：结果会四舍五入（`.5` 远离 0），再按字段下限钳制。比如数量不小于 0，抽取次数不小于 1。药水等级以“等级”作为输入（I 级 = 1）；时长为 0（无限）时不经过修饰器。

## 4. 在指令和脚本里使用

连接[游戏开发服务器](#game-dev-server)后，点击药水或音效文本框会自动展开游戏目录，直接输入即可搜索；药水显示游戏本地名称和图标。指令输入提供原版补全，上下键选择、Tab 或 Enter 接受。音效列表每行右侧的播放图标用于在游戏中试听，试听不会选择该条目，停止入口位于游戏聊天。离线仍可手动填写。

礼包表单引用独立的礼包脚本，提供搜索选择、打开、新建和旧代码提取。独立脚本编辑器在线时使用浏览器 Worker 中的 Python 语言服务；`kit`、`random` 等有类型提示，通过 `.pyi` 获取 Java API。首次连接游戏时需要初始化；离线立即停止语言服务并清除诊断，仍可编辑和撤销，重连自动分析最新草稿。补全与运行脚本相互独立。

指令中可以用 `${表达式}` 插值。表达式里不能写 `x`，但可以读超参数、调用修饰器：

```text
give @s minecraft:apple ${round(loot(5))}
```

需要输出字面量 `${` 时写 `$${`。插值出错的指令行左侧会显示红条，悬停可以看到原因。游戏内执行时 `@s` 为领取玩家，由引擎以服务端身份跑指令（见 [引擎发放契约](#kit-runtime)）。

引用的礼包脚本里，引擎会注入 `kit`、裸 `ServerPlayer` 的 `player`（以及本次 `grant` 的 `players` 列表）：`kit.param("intensity")`、`kit.mod("loot", 5)`，物品请直接调玩家库存等游戏 API。表达式接口见 [表达式标准 V1](#kit-expr) 第 12 节；**多人一次 grant、注入表、发放顺序、失败语义**以 [引擎发放契约](#kit-runtime) 为准。

## 4.1 领取反馈

**领取反馈** 卡片编辑 `message` / `title` / `subtitle`（及音效）。文案走礼包本地化；卡片上就是唯一的可编辑富文本框（直接输入、拖选）。聚焦后弹出样式工具条：点颜色 / 样式作用于选区，未选中则作用于全文；**清除样式**去掉选区（或全文）颜色与字形。分段由编辑器自动拆合。

- 无样式时本地化值仍是普通字符串；
- 有颜色或多样式时存 JSON 文本组件（与原版 `Component` 一致，支持 `"color":"#FFAA00"`）。

引擎须按文本组件解析后再发聊天 / title / subtitle，见 [引擎发放契约 §4.5](#kit-runtime)。

## 5. 编译结果

表单最底部的 **编译结果** 是一份只读表单，布局与上方的可编辑表单完全相同。它读取当前礼包，并按超参数的预览值应用修饰器，直接展示最终会发放的内容：

- 物品数量、抽取次数、权重、药水等级和时长、经验都是最终值；被修饰过的字段旁标有 `ƒ 修饰器名`；
- 指令已完成插值；
- 所有错误和警告也汇总在这里，包括修饰器错误、绑定缺失、插值失败。

## 6. 独立礼包定义

每份 `.kit` 独立声明全部内容、参数、修饰器与标签，不引用其他礼包。`extends` / `includes` 字段已移除，包含这些字段的旧文件会报错；编辑器保留原文并暂停编辑，导出也拒绝旧格式。需要先将原有内容整理成完整的独立礼包。

编译结果按预览值应用当前礼包的修饰器与插值，不从其他礼包补充内容。物品模板引用和有序脚本列表继续支持。

## 7. 文件格式

```json
{
  "tags": ["daily", "event/summer"],
  "params": [{ "id": "intensity", "kind": "float", "default": 1, "hint": "奖励强度" }],
  "modifiers": [{ "id": "loot", "label": "掉落倍率", "expr": "x * intensity" }],
  "items": [{ "id": "minecraft:apple", "count": 5, "mods": { "count": "loot" } }],
  "effects": [{ "id": "minecraft:speed", "amplifier": 0, "duration": 30, "particles": true, "mods": { "duration": "loot" } }],
  "experience": { "kind": "points", "amount": 10, "mods": { "amount": "loot" } }
}
```

后端引擎应按 [表达式标准 V1](#kit-expr) 第 9 节计算最终值。

## 内嵌物品的组件

内嵌 ItemStack 与物品库共用 [TNBT JSON](#tnbt-json) 完整组件集合；`.itemstack` v3 导入后保留数量与所有带类型的值。物品链接仍只保存引用与数量，不复制组件。点行内 `{ }` 打开**弹窗表单**编辑组件（复用常用组件卡片与 type / key / value 类型树）；链接物品的组件弹窗只读，需回物品库修改。

旧版普通 JSON 组件值不再推断转换。旧 `.itemstack` 需从支持 TNBT JSON v3 的新版 Mod 重新导出。组件集合为空表示没有组件，不会补齐原版默认值。

礼包引用格式与旧代码提取见[脚本资源](#script-resources)，统一补全规则见[Python 语言服务](#python-language)。

### 多脚本绑定

`script` 保存有序引用数组，例如 `"script": [{"ref":"基础发放"},{"ref":"额外效果"}]`。同一脚本不能重复绑定。发放前验证全部引用，缺失任意脚本则整次发放失败、不会先发奖励。每位接收者依列表顺序执行；各脚本有独立调用环境，使用相同 kit/player/players 与连续随机数源。脚本抛错会终止该接收者后续步骤，已有副作用不回滚。脚本只执行当前礼包声明的列表。

WebUI 支持从资源管理器拖入礼包脚本、拖动排序、点击名称打开，行末 × 解除绑定。添加菜单包含已有脚本和“新建并绑定”；旧内嵌代码仍须显式提取。
