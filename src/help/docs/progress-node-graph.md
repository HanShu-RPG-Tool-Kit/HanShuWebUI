# 多进度节点图：节点、端口与信号

本文只描述**画布上实际存在的东西**：有哪些节点、节点有哪些端口、哪些线合法、信号怎么走、模拟器怎么跑。模型语义见 [多进度任务模型](#progress-flow-model)；画布交互规范见 [通用节点编辑器接入规范](#node-editor)。

## 1. 图与文档的对应

`.quest` 的 `format` 为 `hanshu.progress-tree`、`version` 为 1。

| 文档部分 | 内容 |
|---|---|
| 开始 | `start`：唯一的「开始进度节点」ID，必须存在于 `progress`。任务标题放在该节点的 `questTitle` 上 |
| 节点集合 | `progress`、`predicates`、`transitions`、`ends` |
| 连线 | `logic.links: { id, from, to, port, fromPort? }[]`；`port` 是目标输入口，`fromPort` 是来源输出口 |
| 布局 | `layout.positions` / `layout.notes` / `layout.groups`，只影响画布 |

- 节点 ID 在整张图内唯一（跨集合也不能重名）。
- **唯一连接约束**：只能从右端口连到左端口，且**不能成环（含自环）**。连接时直接拒绝；文档里手写出环是校验 error。
- **内容**：只有开始进度节点有 `questTitle` / `description`；所有进度节点有 `title` / `runningLog`（进行时日志）/ `completedLog`（完成时日志）/ `goals` / `completion`；结束节点有 `title` / `rewardKits`；谓词有 `title` / `conditions`。文案都是可本地化的 `FlowText`。

## 2. 节点族总表

| 集合 | 画布标题 | 尺寸（宽×高） | 输入口 | 输出口 | 运行态 |
|---|---|---|---|---|---|
| `progress`（`start`） | 开始进度 | 216×118 | **无** | `output`（成功）、`output2`（失败） | 未激活 / 运行中 / 已成功 / 已失败 / 已取消 |
| `progress`（普通） | 进度 | 216×118 | `input` | `output`、`output2` | 同上 |
| `predicates` | 谓词 | 200×84 | 无 | `output` | 真 / 假（模拟器切换） |
| `transitions` | 变迁 | 180×96 | `input`（合取）、`input2`（析取） | `output`（通过） | 一轮查询的临时簿记 |
| `ends` | 结束 | 168×84 | `input`（成功入）、`input2`（失败入） | 无 | 已到达（成功 / 失败） |
| `layout.notes` | 注释 | 自定义（≥160×96） | 无 | 无 | 不是内容节点 |

**端口颜色**：成功口绿、失败口红、激活口蓝；变迁合取口金、析取口蓝；谓词紫；结束成功入绿、失败入红。

### 2.1 开始进度节点

- 任务里**有且只有一个**，由根上的 `start` 指定；不可删除。
- **没有左端口**，所以任何线都连不进去；不能靠 A 激活。
- 任务开始时（模拟器「触发开始」）**直接进入运行中**。
- 有两个右端口（成功 / 失败），和普通进度一样可以结算；结算后沿对应端口发 A。
- 额外内容：`questTitle`（任务标题）与 `description`（任务说明）。

### 2.2 进度节点

- 一个左端口 `input`（多线），两个右端口 `output` 成功 / `output2` 失败（各多线）。
- 内容：`title`、`runningLog`（运行中显示的任务日志）、`completedLog`（结算时显示的日志）、`goals`、`completion`（`all` / `any` / `custom`，自定义时带 `completionGraph`）。
- 收 **A**（`input`）：未激活 → 运行中，**同时向左端口发 C**（激活即消费输入：上游不必再为它等待或重复触发）。其它状态下的 A 忽略。
- 结算（模拟器手动）：运行中 → 已成功 / 已失败，并从对应端口发 **A**。
- 收 **Q**：已成功且 Q 到成功口 → 回 **A**；已失败且 Q 到失败口 → 回 **A**；其余回 **N**。
- 收 **C**：运行中 → 已取消（不转发）；未激活 → 从左端口向上游转发 **C**（自身仍为未激活，之后仍可被激活）；已成功 / 已失败 / 已取消 → 忽略。

### 2.3 谓词节点

- 没有左端口，一个右端口（多线）。**没有运行状态**：它只是一个全局事实源。
- 内容：`title` 与 `conditions`（与单进度任务的可见性条件同一套 `task` / `dialogue` / `expr` / `repeat`，组内取「与」）。
- **空条件恒假**：不会成立。
- **A 是边沿**：假 → 真时向下游广播一次 A；一直为真不重复；真 → 假不发信号。
- **Q 是电平**：按**当前**真值回答 A / N，所以晚到的消费者也能读到已成立的事实。
- 收 **C**：忽略。谓词不归任何消费者所有，谁也不能把它关掉。
- **实例初始化时整体播报一次**：见 §8。之后只按上升沿增量广播。

### 2.4 变迁节点

- 左端口两个：`input` **合取**、`input2` **析取**，均可多线；右端口 `output` 可多线。没有内容。
- 收到 **A**：开启一轮，向两个左端口发 **Q**；收齐应答后判定：
  - 合取端口（非空）要求**全部** A；析取端口（非空）要求**任一** A；
  - **所有非空端口都满足**才从右端口发 **A**，同时向两个左端口发 **C**（消费输入）；
  - 不满足则本轮静默结束；之后任一 A 重新开启一轮。
- 收 **C**：向两个左端口转发 **C**。收 **Q**：回 **N**。

### 2.5 结束节点

- 两个左端口：`input` 成功入、`input2` 失败入，均可多线。
- 收 **A**：从哪个入口进来就记录哪种任务终局；第一个有效投递锁存整个 quest 的 `{endId,result}`，立即终止传播。尚未投递的信号进入丢弃记录，不再送达，不覆盖终局。
- 终局前已处理的状态保留；其他运行中进度直接标记为 `terminated`（随任务结束），不算失败，也不广播 C。此实例拒绝后续业务事件；只有重置才能重新运行。奖励只允许由胜出结局触发一次；模拟器不发放真实奖励。
- 内容：`title`（结局标题）与 `rewardKits`（奖励礼包引用列表）。
- 可以有很多个结束节点；没有任何**与开始联通**的结束节点是校验 warning。

### 2.6 注释

- 存在 `layout.notes`，不是内容节点：不可连线。字段 `title` / `text` / `width` / `height` / `color`。

### 2.7 表单视图

- **双击节点**（或 Enter / F2）在画布上打开该节点的表单视图：一张更大的、没有端口的卡片，跟着画布平移缩放。
- **每个节点最多一张**：再次双击只保持原视图，不会开第二张；可以同时打开多个节点的视图。
- 视图可拖动，但位置只在**当前会话**有效，不写入 `.quest`、不参与校验、不进 Group、不可连线。
- 内容随改随写回文档（走工作区既有的撤销 / 保存）。
- 表单内容：开始进度与普通进度是任务/进度文案、两段日志、目标与完成判定；谓词是条件组；结束是结局标题与奖励礼包。变迁没有表单。
- 空白处右键「编辑任务信息…」等同于打开开始进度节点的表单。

## 3. 连线规则

- 来源必须有对应的右端口，目标必须有对应的左端口。
- **不能成环**：若从目标能顺向走回来源（含来源等于目标），连接被拒绝。
- 结束节点与谓词没有出/入口的组合天然被端口表挡住（谓词无左端口、结束无右端口、开始无左端口）。
- 幂等：同一条 `from`/`to`/`port`/`fromPort` 重复连接不会产生第二条线。

常见形态：

| 想表达 | 连法 |
|---|---|
| 进度后接一个阶段 | 进度`成功` → 变迁`合取`；变迁`通过` → 下一进度`激活` |
| 成功 / 失败分叉 | 进度`成功` / `失败` → 不同进度或结束节点 |
| 合取（全部满足） | 多个进度/谓词 → 同一个变迁的 `合取` |
| 析取（任一满足，其余作废） | 多个进度 → 同一个变迁的 `析取` |
| 谓词门 | 进度 → `合取`；谓词 → `析取`（两个非空端口都要满足） |
| 任务终局 | 进度或变迁 → 结束节点的 `成功入` / `失败入` |

## 4. 信号

| 记号 | `kind` | 方向 | 含义 |
|---|---|---|---|
| **A** | `activate` | 顺流 | 我被激活 / 我成立 / 这是我的结局 |
| **Q** | `query` | 逆流 | 你现在是什么状态？ |
| **C** | `cancel` | 逆流 | 这个消费者不要你了 |
| **N** | `none` | 逆流 | 对 Q 的否定应答；任何未特别说明的节点收 Q 都回 N |

- **顺流**：沿输出口 → 连线的目标输入口；**逆流**：沿输入口 → 连线的来源输出口。
- 线上只有这四种；成功与失败由**端口**区分，A 不携带原因。
- **C 谁发**：变迁放行时向两个左端口发；进度被激活时向左端口发；未激活的进度收到 C 时继续向上游转发。谓词与已结算的进度忽略 C。

## 5. 进度状态机

```text
未激活 --A--> 运行中（并向左端口发 C） --结算--> 已成功 | 已失败
运行中 --C--> 已取消
未激活 --C--> 未激活（向上游转发 C）
已成功 / 已失败 / 已取消 --C--> 忽略
```

- 开始进度节点由「初始化任务」直接进入运行中（不走 A，也没有左端口可发 C）。
- A 只对**未激活**生效；其余状态幂等忽略。
- **激活即消费输入**：一次 A 会让左端口上的**所有**连线都收到 C。链式图里上游此时都已结算（C 被忽略），不影响推进；同一端口存在多个候选上游时，先激活的分支会消费掉其余候选（先到者赢）。
- 状态只在模拟器内存里，**不写进 `.quest`**。

## 6. 变迁的一轮查询

```text
收到 A（触发） → 开启第 n 轮，向两个左端口发 Q（携带轮次号 n）
各输入回 A / N → 收齐本轮所有入线的应答后判定
满足 → 右端口发 A，两个左端口发 C，本轮结束
不满足 → 本轮结束（不发 C）；之后任一 A 重新开启第 n+1 轮
```

- 应答携带**轮次号**：上一轮的迟到应答会被吞掉，不会误开新一轮。
- N 表示「此刻不满足」，不表示「永远不」；之后结算时发出的 A 会被下一轮重新问到。
- 没有入线的变迁收不到 A，永远不会放行。

## 7. 草稿节点

- 与 `start` **联通**的节点才是**生效节点**；其余是**草稿节点**。联通性把连线视为**无向边**——谓词只有出边，按有向可达会永远判成草稿。
- 草稿节点在画布上变暗、带「草稿」徽标；校验给 warning；草稿谓词允许预置真值，但初始化与之后的真值变动都不广播。
- 把草稿接进联通分量后立即转为生效。

## 8. 实例初始化

初始化发生在**首次接取**与**读档（load）**，同一实例只做一次（模拟器「重置模拟」后可以重做）：

```text
1. 开始进度节点进入运行中
2. 对每个生效谓词按当前世界真值求值（不是用缓存）
3. 按节点 ID 的稳定顺序，为真值谓词各广播一次 A
4. 运行信号队列
```

- **只广播已为真的谓词**；假的什么都不发。
- 只播报**生效谓词**（与开始进度联通）；草稿谓词不参与。
- 稳定顺序保证同一存档重放结果一致。
- 初始化之后，谓词只在 **假→真** 的上升沿增量广播；不再周期性扫描。
- 重复初始化是空操作；要重放需先重置实例。

引擎侧约束：谓词条件可以引用别的任务状态，所以**所有 quest 实例的状态应先全部加载完，再统一初始化和广播**；否则会按半加载状态广播出错误事实。

## 9. 信号顺序与终局边界

每次外部事件开启一个 `pulse`，期间不得插入其他事件。所有投递共用一个 FIFO 队列：取出队首，接收者原子地完成状态变化与判定，产生的投递追加到队尾。**入队不代表送达。** 单步恰好完成一条投递；动画阶段不允许另一投递插入节点判定。

### 9.1 局部分支顺序

连线增加 `order`（顺流）与 `reverseOrder`（逆流），都是非负整数，值越小越先入队：

- `order` 的范围是同一源节点、同一输出端口；`reverseOrder` 的范围是同一目标节点、同一输入端口。
- 当前 quest 画布是横向布局：顺流按接收节点 **y、x** 排序，逆流按上游接收节点 **y、x** 排序；相同坐标按连线 ID 的 UTF-16 码元字典序比较（不使用 localeCompare）。这些序号不是全图执行排名。
- 连接、移动节点时重新生成局部序号并随业务修改保存。新增的连线会参与所在端口重新排序；画布表单不参与排序。
- 缺少序号的旧图在解析/导出时按相同规则补齐；缺布局的位置视为 `(0,0)`。已有完整序号以其为准，引擎不读取坐标。相同序号按上述 ID 比较兜底。
- 任意重排 `logic.links` 数组不得改变运行结果。圆形序号显示在分支连线上；靠源端为顺流，靠目标端的淡色序号为逆流。
- 引擎移植必须使用相同整数排序、缺省输出端口规范化和 ID 比较规则，不能使用容器迭代顺序。后续若增加纵向 quest 布局，再明确其排序轴；当前没有从镜头或视口方向猜测顺序的行为。

### 9.2 生成顺序

初始化先让开始进度运行，再按谓词 ID 的 UTF-16 顺序播报生效真谓词；每个谓词内部按 `order`。进度结算从对应输出端口按 `order` 播报；生效谓词假→真同理。

| 投递 / 判定 | 新投递的入队顺序 |
|---|---|
| 变迁收 A 开启查询 | `input` 的 Q，再 `input2` 的 Q；各端口按 `reverseOrder` |
| 变迁收齐本轮应答且放行 | 下游 A，再 `input` 的 C，最后 `input2` 的 C |
| 进度收 A | 变为运行中，然后从 `input` 按 `reverseOrder` 发 C |
| 进度收 C 且未激活 | 向 `input` 按 `reverseOrder` 转发 C |
| 进度结算 | 先改自身状态，再从对应出口按 `order` 发 A |
| 谓词变真 | 从 `output` 按 `order` 发 A |
| 结束节点收 A | 锁存唯一终局，终止本次传播，剩余队列全部丢弃 |

Q 的应答沿原通道回到发起方，并携带查询轮次。相同轮次、相同连线的第一个应答被记录；重复和迟到应答不能覆盖已经记录的值或启动新查询轮次。

**不同外部事件的先后仍然是业务语义。** 位置序号只确定一次 fanout 内的顺序，不会让队列深处的“高优先级”信号跳到队首。若作者希望多个分支均完成才结束，必须在结束节点前显式汇合；终局不会等待队列排空。

### 9.3 执行安全契约

- 运行图最多 **512 个业务节点、4096 条连线、每端口 128 条连线**；禁止环、重复连线与非法端口。模拟运行及多进度导出都检查，超限拒绝执行/导出。
- 同一 pulse 中，相同接收节点、接收端口、进度状态和变迁轮次的 C 只处理一次；重复 C 记录为忽略，避免菱形反复展开取消。状态改变或新的查询轮次是不同的处理目标。该去重集合不会跨 pulse 保留。
- 每个 pulse 预算为 `min(250000, max(512, 边数×128 + 业务节点数×32))`，同时限制已处理数与排队/新产生的总数。它是明确的资源限制，**不是所有 DAG 必定能执行完的数学上界**。仅通过结构校验并不免除预算保护。
- 耗尽预算产生 `budget-exceeded` 故障；整次外部事件的进度、谓词、查询、终局和初始化状态回退到事件前检查点。保留调试轨迹并清空待执行队列，重置后才允许继续。不能把部分执行结果当成正常完成。
- 终局与故障不同：正常终局提交终局之前已经发生的变化，丢弃未投递信号；预算故障回退本次事件全部业务变化。
- 传播期间图发生变化也必须停止，不能把旧队列继续送进新图。当前 UI 在初始化后锁定编辑，外部文档变化时停止播放并重置本地模拟。
- 将来引擎接入奖励、脚本等外部副作用时，须在本次传播成功后再提交这些效果，并保证终局奖励幂等；不能依赖模拟器内存回退来撤销外部副作用。

## 10. 可视化模拟器

底部调试栏包含：初始化、单步、播放/暂停、速度（慢速/正常/快速/无动画）、重置、实例终局或故障。初始化前可预置谓词；初始化后锁定图编辑，重置恢复编辑能力。

- **待投递**：队首突出显示，列出 A/Q/C/N、发送者、接收者、端口、查询轮次；点击定位接收节点并选中对应连线。
- **已处理**：区分接收与忽略，并记录原因。历史在新 pulse 开始时保留最近 4000 条，再追加本次受预算限制的轨迹。
- **已丢弃**：终局后的未送达信号及故障中止的剩余信号独立列出，不冒充已处理。
- **详情**：本次投递是否接收、产生几条新信号、哪些节点状态发生变化。长列表当前显示前 100 条并提示总量。
- **画布**：A 绿、Q 蓝、C 橙、N 紫，始终同时显示字母；Q/C 逆流，查询应答沿原通道顺流。节点描边突出最后一次接收或忽略。
- 动画只呈现执行顺序。暂停不继续投递；切到非活动工作区停止播放。无动画仍逐条执行，每条让出浏览器事件循环，结果与单步/带动画一致。
- Ctrl 点击未初始化的开始进度进行初始化；初始化后 Ctrl 点击运行中的进度结算成功（Shift 为失败），Ctrl 点击谓词切换真值。传播未完成时不接受新事件，终局/故障后必须先重置。
- 队列、日志、播放速度、终局及故障均是本地模拟状态，不写 `.quest`，不提交协作事务。`order` / `reverseOrder` 属于持久业务数据。

验证入口：`npm run test:quest-signals`、`npm run test:quest-simulator:ui`、`npm run test:progress`、`npm run test:quest-compile`。浏览器截图保存在 `node_modules/.cache/quest-simulator/`。

## 11. 校验清单

**结构解析失败**：格式/版本不符、`start` 缺失或指向不存在的进度、`progress` 不是对象、节点 ID 跨集合重复、`FlowText` 带 `key`、旧草稿字段（`entry` / `nodes` / `goals` / 根级 `name` / `description` 等）、变迁/结束带旧内容。

**语义 error**：超出图/端口规模限制、重复连线；开始进度不存在；连线端点不存在或端口不对；成环；Group 引用不存在的节点 / 重复分组；进度内目标 ID 为空或重复。

**warning**：任务未命名；草稿节点；没有任何与开始联通的结束节点；进度内目标未选类型；谓词没有条件（恒假）或条件缺少对象。
