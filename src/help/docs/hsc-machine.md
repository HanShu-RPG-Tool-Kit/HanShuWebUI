# 抽象汉书自动机（HSC Machine）

本文约定 **`.hsc`（及等价语句序列）的标准执行模型**。  
作者写法以 [.hs 语法说明](#hanshu-syntax) 为准；本文只谈**机器怎么跑**。

RPGToolKit 里的旁白、自白、对话、会议、过场动画等消费者，应在本抽象机之上叠加守卫、伴随行为或 timeline，而**不改写**这里的控制流语义。

实现分层（Machine Type / Instance、钩子、能力与拒绝、**可实例化**且不规定分配方式）见 [HSC 机器实现框架（标准参考）](#hsc-machine-framework)。

非法 / 不合语法的文本：**本文不约定**行为（加载前应由编译与校验拒绝）。

---

## 1. 组成部分

| 部分 | 含义 |
|------|------|
| **线性内存** | 储存文本序列：一行一条语句（或选项树中的一行） |
| **程序计数器（PC）** | 读头当前指向哪一行 |

可选实现细节（树的具体数据结构、UI 怎么画）不在抽象机范围内。

### 与语法组件的对应

| 行类 | 自动机角色 |
|------|------------|
| 对白（`speaker:…`） | 可执行语句 |
| `!id args…` | 行为信号（函数，返回 void） |
| `?id args…` | 条件信号（函数，返回布尔）；只作为选项前置附件 |
| `!:id` / `:!id` | 选项 / 答复行为信号（返回 void）；只作为选项前置附件 |
| `-` / `--`… 选项行 | 组成**选项树**（见 §5） |
| `@name` | 注入点标签（运行时跳过） |
| `@@…` | 终止符 → **停机** |

信号一律视为**函数**：元数与参数由外部驱动器解释；抽象机只约定**何时调用**与**返回值形态**：

- `?` → 必须是布尔（真 / 假）
- `!` / `!:` / `:!` → 必须是无（void）

---

## 2. 初始状态

1. 内存已填入合法的 `.hsc`（或等价序列）。
2. **PC** 一般落在某个注入点，例如 `@dialog_hello_world`（由消费者约定入口名）。

从该行开始按 §3 步进。

---

## 3. 线性规则（PC 扫描）

机器反复查看 **PC 所指行**，按下列规则之一处理。  
（进入选项树会话期间，线性扫描暂停，见 §5。）

### 3.1 对白块

1. **执行**对白（如何呈现由消费者决定）。
2. **PC ← 下一行**。

### 3.2 行为信号 `!id args…`

1. **发射**该信号（调用驱动器，返回 void）。
2. **PC ← 下一行**。

「发射」在实现上**通常就是同步调用驱动器**（阻塞到函数返回）——这完全没问题。  
抽象机说的「不显式阻塞」是另一层意思：见 §7。

### 3.3 注入点 `@…`

1. **无视**（不当作可执行内容）。
2. **PC ← 下一行**。

约定（语法层）：注入点名字在**整个工作区**跨 `.hs` **全局唯一**（大小写不敏感）；重复名非法。`:>>name` 按名字解析到任意文件中的 `@name`（编译接线符号 `hsInject`）。

### 3.4 终止符 `@@…`

1. **停机**。
2. 停机后是否移动 PC：**不约定**（无后续语义）。

### 3.5 选项树起点

若当前行属于一棵选项树的范围内（见 §4），转入 §5，**不再**对树内每一行做线性 3.1–3.4。

---

## 4. 选项树的行范围（打断规则）

一棵选项树 = 从某个**顶层** `-` 行起，到被打断为止的连续相关行（含 `--` / `---`… 子级，以及紧贴选项的前置附件行）。

### 打断（结束当前树的文本范围）

下列行**不属于**当前树，并作为范围终点之前的边界：

- 对白行（`speaker:`）
- `@` 注入点 / `@@` 终止符
- **空行**
- 独立行为信号行（`!id …`）

### 不打断（仍算在树内）

- `#` 注释（`.hsc` 中通常已去掉）
- 选项前置附件：`?` / `!:` / `:!`（须紧贴其所约束的选项行，见语法说明）

**说明：** 合法树上**不会出现** `@@`；若运行中遇到 `@@`，只可能来自 `:>>` 跳转到树外之后的线性扫描。

---

## 5. 选项树会话

### 5.1 进入

1. **确定树对应的行范围**（§4）。
2. **PC ← 该范围最后一行的下一行**（先记好「树后继续点」，再交互）。
3. **建树**（具体结构不限）。建树时挂上各选项的前置附件（`?` / `!:` / `:!`）。
4. 令**当前子树根** = 整棵树的根（「默认子树」= 整树）。
5. 进入 §5.2。

### 5.2 展示当前层级菜单

**当前层级选项** = 当前子树根的**直接子节点**。

1. 对每一个将展示的选项：若存在 `?` 条件信号，**此时求值一次**；返回假则**不展示**该选项（剪掉该选项子树对本层的可见性）。  
   - **每次**回到「展示菜单」都重新求值（便于状态变化后刷新可见性）。
2. 把本层可见选项交给用户（交互细节由消费者决定）。
3. 等待用户选择 → §5.3。

### 5.3 用户选择之后

对选中的选项节点，严格按以下顺序（**发射信号**与**执行选项/答复**是两回事）：

1. **发射**选项行为信号 `!:`（若有）——见 §7「不显式阻塞」。
2. **执行选项**（怎么执行不在抽象机范围：可能呈现文案、可能阻塞 UI 等）。
3. **发射**答复行为信号 `:!`（若有）——同上。
4. **执行答复**（见 §5.4）。

然后：

- 若 §5.4 导致**离开树会话** → 从已保存的「树后 PC」继续线性规则 §3（若答复是 `:>>` 跳转，则以跳转后的 PC 为准，见下）。
- 否则 → **回到 §5.2**（再次展示菜单）。  
  回到 §5.2 **之前**不再向用户要一次输入；由模拟器或实际机器维护「选完 → 再展示」的节奏。

### 5.4 执行答复（控制流）

| 答复形态 | 行为 |
|----------|------|
| 普通正文 | 执行答复（如呈现文本）。若该选项是**叶子**（无子选项）→ **退出选项树会话**，PC 已是树后下一行，继续 §3。若仍有子选项 → 将**当前子树根**改为该选项节点，回到 §5.2。 |
| `:<<…`（回退答复） | 执行答复正文（可空）。然后将**当前子树根**重置为**整棵树的根**，回到 §5.2。 |
| `:>>name`（跳转） | **退出选项树会话**，清空选项会话状态；**PC ← 目标 `@name`**，再按 §3.3 扫过标签并继续线性执行（「变回线性」）。 |
| 系统返回选项 `--<` / `--<<` 等 | 见 §6；不经普通答复文案。 |

叶子且答复不是 `:<<`、也不是 `:>>` → **退出树**。  
`:>>` → **退出树**并改 PC。  
`:<<` → **不**退出树，回到整树根菜单。

## 6. 系统返回选项（`--<` / `--<<`）

除普通选项与 `:<<` 答复外，允许一种**系统解析**的选项行，用于导航，**不走汉书本地化键**：

| 写法（示意） | 层级 | 语义 |
|--------------|------|------|
| `--<//`（`.hsc` 可无 `//`） | `-` 个数 **≥ 2** | 返回**上一级**（当前子树根退到父节点；已在整树根时由实现自洽，可重开根菜单） |
| `--<<//` | `-` 个数 **≥ 2** | 返回**整棵树根**（与 `:<<` 的「回根」同级导航意图，但是独立选项） |

规则：

- **层级必须大于 1**（至少一个 `--`）；顶层 `-` 不得使用 `<` / `<<` 系统返回形。
- 更深层级同理：`---<`、`---<<`、`----<`… 只要 `-` 个数 ≥ 2，且其后为单独的 `<` 或 `<<`（无普通文案、无 `:答复`）。
- **同级兄弟**：同一父节点下、相同层数的选项里，`--<` 与 `--<<` **各至多一个**，但**可以各有一个并存**；多个同种非法（见语法说明；机器对非法文本不约定）。
- **展示文案**由 GUI / 消费者本地化（例如「返回」「返回顶部」），**不是** `.lang` 里的剧本键。
- 选中后：不走普通选项的本地化文案路径；可有前置 `?`（控制是否显示）；`!:` / `:!` 罕用。

与 `:<<` 的差别：

- `:<<`：某选项的**答复侧**回根，且可带一段可本地化答复正文。
- `--<<`：单独一个**系统选项**，文案不进汉书 i18n，效果是回根。
- `--<`：回**上一级**（语法说明里的「父级」导航）；`:<<` **不**表示回父级。

## 7. 信号发射与「执行」的次序（选项上）

对带附件的普通选项，选中后固定为：

```text
发射 !:
  → 执行选项（形态不限）
  → 发射 :!
  → 执行答复（正文 / << / >> / 离开树…）
```

线性路径上的 `!` 仍是：发射后 `PC++`，与上式无关。

### 「不显式阻塞」指什么

**不是**「必须做成异步 / 不阻塞线程」。实现上驱动器函数**同步返回**（调用栈阻塞到 `!` / `!:` / `:!` 处理完）是常态，也完全符合本模型。

这里说的是**语义层**：

- 发射信号只表示「把这件事交给驱动器 / 外部系统」；
- **不**表示自动机要一直等到该信号所启动的**长期后果**结束，才能继续下一步。

例子：发射「开始某任务」——驱动器可以立刻把任务标成已接取并返回；自动机接着执行选项、答复、或 `PC++`。  
**并不**要求玩家先把整段任务打完，机器才能动。若某消费者需要「等任务成功再往下」，那是该消费者自己的额外守卫 / 等待逻辑，**不是**抽象机对 `!` 族信号的默认约定。

## 8. 实际汉书自动机（消费者）

抽象机规定：**PC、树范围、菜单循环、信号契约、跳转/回根/回上级、停机**。

`.hs` / `.hsc` 的典型消费者如下（说话人语法仍是 `speaker:…`；这里说的是**谁在跑这段剧本、扮演什么角色**）：

| 消费者 | 参与方 | 驱动力与职责 |
|--------|--------|--------------|
| **旁白** | 一个玩家对自己 | 被动；通常不发或只发射**无副作用**信号；无选项树；不涉及阶段控制 |
| **自白** | 一个玩家对自己 | 同上 |
| **对话** | 一个玩家对某一个实体 | **最重要**的消费者；自驱能力强；常常有选项与信号；是阶段控制的重要组成部分 |
| **会议** | 允许多个演员 | 通常只做演绎，被动；发射无副作用信号；无选项树；**不直接**参与阶段控制（由发起会议的外部驱动者负责） |
| **过场动画** | 允许多个演员 | 同上（由发起过场的外部驱动者负责阶段控制） |

典型扩展（各消费者按需叠加）：

| 扩展 | 例子 |
|------|------|
| 额外守卫 | 仅某任务中允许进入该入口 `@` |
| 伴随行为 | 播 VO、改镜头、记日志 |
| Timeline | 对白与动画轨对齐 |
| 呈现策略 | 打字机、选项列表样式、系统返回按钮文案 |

扩展**不得**改变：树打断规则、`:>>` 变回线性、叶子退出、`:<<` / `--<<` 回整树根、`--<` 回上级、以及 `?` 在每次展示菜单时求值。

如何做成可扩展 Type + 可 `spawn` 的 Instance，见 [实现框架（标准参考）](#hsc-machine-framework)。

| 层 | 职责 |

## 10. 速查

1. 线性：对白 / `!` → 执行后 PC++；`@` → 跳过；`@@` → 停机。  
2. 碰到选项树 → PC 先落到树后 → 建树 → 菜单循环。  
3. 每次展示菜单 → 对可见候选发 `?` 求值。  
4. 选中 → `!:` → 执行选项 → `:!` → 执行答复。  
5. 叶子（非 `<<` / 非 `>>`）→ 退出树，继续树后 PC。  
6. `:>>` → 清会话，PC 到 `@`，线性继续。  
7. `:<<` / `--<<` → 回整树根菜单；`--<`（层级≥2）→ 回上级。  
8. 非法输入 → 不约定。
