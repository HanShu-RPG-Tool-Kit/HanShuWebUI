# `.char` 角色卡语法

角色卡描述一个角色的**可本地化 / 可配音文本槽**。  
执行模型、选项树、信号等与 [.hs 语法说明](#hanshu-syntax) 无关；`.char` **只有一种正文写法**。

---

## 1. 角色 id

- **等于文件名（不含 `.char`）**，例如 `notch.char` → 角色 id `notch`。
- **不要**在文件里再写一层「角色名 = …」之类的标准字段；标准不规定展示名从哪来。
- 作者若需要「名字 / 称呼」等，自行用槽位键承载（见下），引擎是否认哪些键由项目约定，**本标准不规定键名词汇表**。

工程位置：`src/character/*.char`（见工作区资源树「character」分组）。

---

## 2. 唯一正文语法

```char
key:msg//
```

| 部分 | 规则 |
|------|------|
| `key` | `[A-Za-z_][A-Za-z0-9_]*` |
| `:` | 半角冒号 |
| `msg` | 该槽的文本（成键前）或 8 位小写十六进制键名（成键后） |
| `//` | **必须**在行尾，与 `.hs` 单行对白相同 |

另允许：

- 空行
- `#` 行注释（行首，可含前导空白）
- 顶格 `#stopparse`：其后不再自动成键（与 `.hs` 相同）

**没有**多行块、选项树、信号、`@` / `@@`、系统返回等。

### 正例

```char
# notch.char — 角色 id = notch
name:Notch//
title:建筑师//
greeting:嘿，朋友。//
```

成键后正文形如：

```char
name:a1b2c3d4//
title:e5f60718//
greeting:90abcdef//
```

对应语言文本：`assets/<语言标签>/lang_char/notch.lang`；  
配音：`assets/<语言标签>/voice_char/notch/<键名>.ogg`。

### 反例

```char
# 错误：缺行尾 //
name:Notch

# 错误：中文键名
名字:Notch//

# 错误：多行块（.char 不支持）
bio:
很长一段话
//
```

---

## 3. 本地化与配音

与 `.hs` **同一套**机制：

- 敲下行尾 `//` 后自动成键（文本哈希）；映射进 `lang_char`
- 录音棚 / TTS 按键列表工作；打开 `.char` 即可配音
- Agent：`parse_hs` / `unparse_hs` / `list_lang_keys` / `write_lang` 等对 `.char` 同样可用（按源后缀选解析器）

展示名用哪个 `key`、要不要配音，由作者与引擎约定；**语法层不区分「名字槽」与其它槽**。

---

## 4. 导出

- 源文件平面：`client`（与 `.hs` 同类）
- 一般**不**再编译成中间格式；随包带上 `.char` 原文 + `lang_char` / `voice_char` 产物即可

---

## 5. 自检

1. 文件名是否即角色 id？  
2. 每行正文是否都是 `key:msg//`？  
3. 需要翻译/配音的槽是否都已成键并写入对应 `.lang`？
