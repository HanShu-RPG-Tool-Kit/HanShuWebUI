# .progress 进度文档与表单

`.progress` 与 `.hflow` 平级。当前原型格式为 `hanshu.progress`、`version: 1`，不提供旧结构兼容层；不支持的文件保留原文并进入修复界面。

## 数据

- 文档 `id` 是设计文档标识，不表示引擎可识别的任务 ID。`goals` 是一个扁平目标列表，每个目标只有内部 `id`、引用脚本类型的 `kind` 和实例参数 `config`。Goal 的展示语义属于类型定义，实例不覆盖标题或描述。
- `config` 只保存显式填写的参数。缺少某个键表示沿用定义脚本默认值；没有默认值则保持未填写。显式填写等于默认值的值、空文本、零、false 都保留为显式值。恢复默认通过删除对应键实现。
- `completion` 支持 `all`（完成全部）、`any`（完成任一）和 `custom`（自定义完成）。自定义完成使用 `completionGraph`；切换到全部或任一时保留该图，只是不参与完成判断。空目标列表提示待完善。
- Goal 类型及参数字段的唯一来源是工作区「脚本 → 目标定义」及子目录中的定义脚本。目录从 `@goal` / `@config(field(...))` 解析；表单不执行 Python。
- 没有脚本时显示空目录，不自动生成替代类型。定义删除后，现有目标仍保留类型引用和参数，提示恢复脚本或更换类型。未在脚本中声明的旧参数保留在文件中，不推导为新字段。
- `visibility`（可见性条件）和 `acceptance`（可承接条件）是**相互独立**的列表，分别保存三项式条件 `{kind, state, target}`。每份列表内全部条件满足才通过；任意一份为空时，该份条件直接满足，**互不继承、互不蕴含**。模型语义：**承接任务只要求 `acceptance` 满足，不要求 `visibility` 满足**（可以不可见但仍可被系统/流程/脚本等路径承接）；可见只影响展示，不构成承接的前置条件。任务状态为 `before_accept / after_accept / active / succeeded / ended`；对话状态为 `before / after`；求值（`expr`，接条件求值器）状态仅 `true`（满足），`target` 为条件表达式。可见性还可写 `repeat`（重复周期），状态仅 `satisfied` / `unsatisfied`（已满足 / 不满足），`target` 必须为空（指本进度的周期策略）。**可承接数组不得出现 `repeat`**：重复周期以引擎投影进入可承接语义（恒要求周期已满足 / 冷却完毕），表单只作只读说明，不占条件槽、不写入文件。没有独立时态字段。这里只设计条件，引擎求值未实现。任务/对话对象暂为引用文本，资源选择器尚未接入。
- `abandonable`（可放弃）与 `autoStartWhenAcceptable`（可承接时自动开始）为布尔字段；新建文档显式写出，读取时 `autoStartWhenAcceptable` 缺省为 false。后者为真时，在可承接条件满足后自动开始，仍不要求可见。
- `rewardKits` 是去重的礼包引用数组，支持添加多个礼包、逐项移除；没有单礼包限制。
- `authorNotes` 与玩家 `description` 分开。玩家可见的 `name` / `description` 存语义键（固定为 `name` / `description`），译文在 `assets/<locale>/lang_progress/<文件>.lang`；作者备注不本地化。

## 交互

目标使用带 Blender 节点配色的卡片，右上角“完成全部 / 完成任一 / 自定义完成”切换。目标区提供「紧凑 / 列表」两套视图，默认紧凑：按容器宽度自动计算列数，按卡片实测高度紧凑排列，不显示拖拽手柄和上下移动菜单；窄窗自动单列。列表视图单列按文档顺序显示，支持拖拽手柄、上移和下移；拖到条目的上半部或下半部决定插入位置。两种视图均支持参数编辑、独立折叠、复制和删除，不显示内部 UUID。切换不重建卡片，保留尚未提交的输入和折叠状态。视图偏好存本机 localStorage（不可用时仅本次生效），不写入 `.progress`、不改变目标顺序、不产生共享历史。紧凑排版的视觉位置不代表顺序，需要排序时切换列表。

顶部双栏卡片左侧是标题和描述，右侧常显文档 ID、标签和作者备注，小屏幕自动叠放。

参数区使用原生数字输入（整数 step=1，浮点 step=any）、布尔开关、`enum:` 提示对应的下拉框和文本输入。默认值与已填写值有颜色、文字标记区分，可一键恢复默认。数字失焦或 Enter 校验提交，清空后回到继承状态，非法输入不会写入；Esc 取消草稿。换类型保留当前会话的旧参数以便切回。

完成奖励与周期组成双栏，放在目标上方；小屏幕叠放。完成奖励可从左侧「礼包」拖入 `.kit`（或从系统拖入 `.kit` 文件名作引用），也可下拉添加；重复引用会跳过。工程内能找到的礼包在删除按钮旁提供跳转打开。可见性条件、可承接条件分别使用常显卡片，待完善提示也常显。卡片使用礼包编辑器的灰色标题条、平面边框与紧凑间距，标题和描述也采用同款输入边界；周期卡含「可承接时自动开始」与「可放弃」两个 switch（默认前者关、后者开）。「可承接时自动开始」为真时，引擎在 `acceptance` 满足后自动开始该进度，**不**额外要求 `visibility`。可见性条件可选「重复周期」；可承接卡片顶部常显只读「重复周期 / 已满足」投影行。其余条件条目依次为对象类型、状态、对象引用，例如“任务 / 成功后 / 序章任务”。

## 开发试用与验证

`/progress-preview.html` 使用正式组件和同源工作区保存的目标定义脚本，无独立示例类型。工作区脚本保存后可刷新目录。试用表单不写入工程；没有脚本时可以到 `/` 的脚本分区创建。

模型验证：`npx tsx scripts/verify-progress-document.ts`。


## 目标显示别名

目标列表、节点标题和目标选择器统一显示别名。按当前目标列表中类型 `kind` 首次出现的顺序分配 A、B、C…Z、AA、AB…；同类型内依出现顺序编号。例如击杀、收集、击杀、对话、收集显示 A1、B1、A2、C1、B2。排序、删除或换类型后重新计算。

别名不写入文件，也不是引用标识。目标和节点自身的 `id` 仍为 UUID；Goal 节点的 `goalId` 引用目标 UUID，因此列表排序不会改变引用。

## 自定义完成图

选择「自定义完成」后，目标卡片下方展开通用 React Flow 节点编辑器。工具栏或画布右键添加 Goal、逻辑节点；逻辑节点内选择合取、析取、非、二元异或。端口拖动连线、右键删除、多选删除与小刀沿用通用画布操作。完成输出节点唯一且不可删除，可自由移动。

- Goal：无输入，一个单连线 S 输出，参数为 `goalId`。可创建多个引用同一目标的节点。
- 输出：一个单连线 S 输入，没有输出。
- 逻辑：一个可多连线的 S 输入，一个单连线 S 输出；`and/or` 至少一个输入，`not` 恰好一个，`xor` 恰好两个。切换运算如果会超过容量，提示先断开多余连线，不偷偷删除连接。
- S 为布尔状态（目标当前是否完成），不是 `.hflow` 信号模拟器的瞬时消息。逻辑 `not` 取反、`xor` 在两个输入不同时为真。
- 禁止环、重复连接和容量超限。只沿唯一完成输出向上求值，游离节点不参与；有效树缺线或引用已删除目标时标记待完善，不能视为完成。服务端允许保存这种未完成草稿。删除目标保留原引用，画布提示失效，可重新选择。

文件只保存节点、参数和连接，例如：

```json
{
  "completion": "custom",
  "completionGraph": {
    "nodes": [
      { "id": "<node UUID>", "type": "goal", "goalId": "<goal UUID>" },
      { "id": "<output UUID>", "type": "output" }
    ],
    "links": [
      { "id": "<link UUID>", "from": "<node UUID>", "to": "<output UUID>" }
    ]
  }
}
```

逻辑节点写为 `{ "id": "<UUID>", "type": "logic", "op": "and" }`，`op` 可为 `and/or/not/xor`。一张图最多 512 个节点、1024 条连线，图内节点和连线 ID 唯一。

布局不持久化，不占共享历史。打开时按完成树从左向右排列，游离树排列到下方独立区域；本次会话的移动位置保留，切换完成模式不会丢失。工具栏「树形排列」可重新排列，「显示全部」调整视口。新增远端节点没有已知位置时使用自动布局位置。

`completionGraph` 在协作中作为一个语义字段做 CAS，不按节点自动合并。两人修改同一完成图会进入现有冲突处理，独立目标参数修改仍可合并。模式和首次图创建合批提交；服务端回执支持撤销/重做首次创建。WebUI 的 Rust S 负责结构校验和存储，不执行游戏脚本；本次不改 Mod，引擎消费自定义完成图需另行接入。

验证：`npm run test:progress-completion`、`npm run test:progress-completion:ui`、`npm run test:progress-collaboration`。

目标视图浏览器验证：`npm run test:progress-goal-views:ui`，覆盖自适应列数、不同高度卡片、折叠后重排、输入草稿保留、列表拖拽、窄窗溢出与本机偏好恢复。
