# 游戏性工作区

任务（quest）是 HanShu 的内容设计工作区，工作区 ID 仍为 `progress-flow`。顶层资源分类为**任务**；其下「单进度 / 多进度」是按 JSON `format` 划分的**虚拟视图**（非磁盘分区）。执行规则由后续引擎设计。

**节点、端口与信号**见 [多进度节点图](#progress-node-graph)；模型语义见 [进度流程模型](#progress-flow-model)；单进度表单见 [任务文档](#progress-document)。

## 多进度文档

新建一律 **`.quest`**：多进度 `format: "hanshu.progress-tree"`、`version: 1`；单进度 `format: "hanshu.progress"`。这些是原型实现细节；现阶段不做专用 Git 合并。

```json
{
  "format": "hanshu.progress-tree",
  "version": 1,
  "id": "a-stable-document-id",
  "start": "progress_start",
  "progress": {
    "progress_start": {
      "identifier": "start",
      "questTitle": { "text": "progress.progress_start.questTitle" },
      "description": { "text": "progress.progress_start.description" },
      "runningLog": { "text": "progress.progress_start.runningLog" },
      "completedLog": { "text": "progress.progress_start.completedLog" },
      "goals": [],
      "completion": "all"
    }
  },
  "ends": { "finish": { "title": { "text": "ends.finish.title" }, "rewardKits": [] } }
}
```

- 根上的 `start` 指向**唯一**的开始进度节点；任务标题是它的 `questTitle`，任务说明是它的 `description`。
- 开始进度节点没有左端口，任务开始时直接进入运行中；不可删除。
- 所有进度节点（含开始进度）和目标节点必须填写非本地化 `identifier`；只有条件节点可选填写，空值代表匿名。所有非空标识符共享 quest 内唯一命名空间，与稳定节点 ID 分离；任务标题 `questTitle` 仍需本地化。目标和进度使用同一提交方式控件：UI 无参数，对话注入点填写不带 `@` 的名称；类型和参数不本地化。进度自身只配置一次、提交全部 goal，内嵌 goal 不配置提交。含交付型 goal 却未配置入口会报错。
- 其余节点：普通进度（阶段状态，带 `runningLog` / `completedLog` / `goals` / `completion`）、条件（`conditions`，空条件恒假）、目标（`objectives`，一个 `goal`，随任务启动且不维持存活）、逻辑、结束（`title` + `rewardKits`）。目标不进入任务 UI 跟踪，实例执行 goal；图模拟器只手动结算和发信号。节点按稳定 ID 平铺保存，`FlowText` 只含 `text`。
- **唯一连接约束**：右端口 → 左端口，且不能成环（含自环）。连接时拒绝，文档里手写出环是校验 error。
- 与开始进度节点**联通**的节点是**生效节点**，其余是**草稿节点**（画布变暗，校验 warning）。联通性把连线视为无向边，否则只有出边的条件永远会被误判成草稿。
- 可选 `layout.positions` 单独保存 `{x, y}`（允许负数）；拖动只改位置。没有手工位置时按图结构初次排列。可选 `layout.groups` 保存 `{name?, nodes}`，只表示一起移动。可选 `layout.notes` 保存画布注释。
- 文档根上的 `id` 是作者可控的稳定文档身份（默认 UUID，非空且 ≤200），**允许修改**，不会改写图内引用；文件名在资源管理器改名。

## 工程服务

任务与剧本共用同一全局工程连接，文件读写统一经过 S。源文件与语言/配音资源共用写权，保存只提交变更。详见[工程服务与多人协作](#collaboration-service)。

## 编辑与保存

- 左侧资源管理器顶层分类：**脚本**、**任务**、**演员**、**声誉**、**区域**、**导航器**、**商店**、**礼包**、**物品库**、**实体库**（各分类下可有文件夹）。「任务」下有两个**虚拟视图**——**单进度任务**（`hanshu.progress` 表单）与**多进度任务**（`hanshu.progress-tree` 树图）；磁盘一律 `src/quest/*.quest`。「脚本」下内置二级分类 **目标定义**（稳定、不可重命名/移动/删除），其内另有虚拟只读 **内置**。可新建 / 导入 **`.py`**。「任务」新建 **`.quest`**（菜单区分单/多进度作者态）；可导入 `.quest` / `.json`。「导航器」→ **`.nav`**。「物品库」→ **`.item`**；可拖入 **`.itemstack`** 转成 `.item`。「礼包」→ **`.kit`**。「商店」→ **`.shop`**，模板语义及实例边界见[商店模板](#shop-guide)。其余分类暂只支持文件夹占位。
- **工程目录**：与剧本同一包根。任务落在 `src/quest/`；另有 `src/shop/`、`src/navigator/`、`src/items/`、`src/entities/`、`src/gift/`、`src/script/<类型>/`。编辑写入共享工程会话；任务区「保存」/Ctrl+S 整包落盘。未打开工程时只读。UI 状态存 `hanshu.progressUi.v1`。
- **本地化**：`.quest` / `.nav` / `.kit` / `.shop` 与 `.hs` 同布局——源存语义键，译文在 `assets/<locale>/lang_<后缀>/….lang`（任务为 **`lang_quest`**）。键为文档内相对路径（如 `progress.<id>.questTitle`、`progress.<id>.runningLog`、`ends.<id>.title`），不含文件名；改名时搬迁对等 `.lang`。作者备注、画布注释、礼包音效 id / 标签 / 指令、`.item` 标签不进本地化。
- 主区按 VS Code 方式划分**编辑组**，每组有自己的**文档页条**：打开即加入、可拖拽排序；右键可固定、关闭、关闭其他页、关闭右侧页、关闭所有页；固定页跳过关闭。最多两组，支持拖到边缘拆分、跨组移动与「合并拆分」，分割线可拖动、双击恢复对半。
- 右键资源可打开属性、重命名、移动、导出校验通过的树图、下载原始草稿或移除；支持拖动文件和文件夹到目录，禁止移入自身或子目录。文件夹是资源树的**视图归属**（存于 `hanshu.progressUi.v1`），磁盘与 `lang_*` 仍按文件名扁平；**重命名只改文件名**，换文件夹用「移动到」。**同一分类内文件名全局唯一**，文件夹名仅同级唯一。
- 可从系统资源管理器拖入或多个文件粘贴到分类/文件夹：脚本接受 `.py`，任务接受 `.quest` / `.json`，物品库接受 `.item` / `.itemstack` / `.json`，礼包接受 `.kit`，商店接受 `.shop`。
- 资源树支持多选、批量删除、键盘导航与就地重命名。

## 画布

- 单击选择；双击进度 / 条件 / 目标 / 结束节点在**画布上**打开该节点的表单视图（每个节点最多一张，可同时开多个，位置只在会话内有效），也支持 Enter / F2。任务信息通过开始进度节点的表单或空白处右键「编辑任务信息…」编辑。
- 空白处右键或工具栏「＋ 节点」创建**进度 / 条件 / 目标 / 逻辑 / 结束**和注释；右键创建使用鼠标位置，工具栏创建使用当前视野中心。双击空白画布不创建节点。
- 拖动节点调整位置，松开后保存为一次可撤销编辑。框选、Shift/Ctrl 追加选择；Ctrl+G 建 Group、Ctrl+Shift+G 解除。Group 标题双击重命名。
- 拖动右侧输出端口到左侧输入端口连线，也支持反向拖；松开到空白处或 Esc 取消。**端口不匹配、会成环（含自环）或目标不存在**时连接被拒绝。重复连接同一对端口会选中已有连接。
- 单击连线选择，Delete / Backspace 或右键「断开连接」移除；多选可一次断开。连线与断开都记为一次撤销。
- 右键拖动平移无限画布；滚轮以指针为中心缩放（20%–250%）；工具栏提供缩放、「显示全部」「定位开始」。双击后第二次按住拖动为小刀，划过的连线一次断开（一次撤销）。
- 信号模拟器：工具栏「初始化任务」让开始进度节点进入运行中，并按当前真值**整体播报一次**已为真的生效条件；「重置模拟」清空运行时。初始化之前切换条件真值只算预置，不发信号；初始化之后只在 假→真 时广播。右键菜单可结算进度、切换条件真值；Ctrl+点击开始进度（初始化）、条件（切换真值）、运行中的进度（结算成功，Shift 为失败）。模拟结果不写入文档。
- 结构错误时在主区直接编辑源码；语法与容器形状恢复后自动回到画布。
- 每份文档有会话内撤销/重做（Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y）；资源目录操作独立于文档历史。
- 本机草稿库使用 `hanshu.progressWorkspace.v1`，原始未完成源码也会保存；读取失败时阻止自动覆盖。
- 导入 `.quest` / 原生 JSON；导出通过结构校验的树图，或下载未经校验的原始草稿。

## 校验

覆盖：开始进度节点存在且不可删除、任务 ID 与节点 ID 唯一、端口匹配、**成环是 error**、Group 引用、坐标、结束节点入口、进度内目标 ID。未与开始进度联通的节点报 warning（草稿），没有任何可达结束节点也报 warning。尚未定义任务提取、运行时失效条件、分支竞态、提交事务和复杂等待依赖。

## 验证

运行 `npm run test:progress` 检查文档往返、端口与 DAG 约束、草稿可达性、开始节点不可删除、成功/失败链、并且/或者、条件门、取消与查询、结束终局、位置保存与存储。运行 `npm run build`、`npm run lint` 检查应用。

### 画布注释

空白处右键「添加注释」创建不参与流程、没有端口的说明块。双击或 F2 原地编辑标题与多行文本，Ctrl+Enter 确认、Esc 取消。拖动移动，拖右下角调整尺寸（≥160×96）；右键切换颜色或删除。注释存在 `layout.notes`，参与框选与 Group 联动，但不进入节点/连线模型。

### 多选删除与智能排版

多选后 Delete / Backspace 或右键「删除所选」一起删除进度、条件、逻辑、结束与注释并清理连线；开始进度始终保留，批量操作算一个撤销步骤。多选右键「智能排版」只微调已有布局（对齐行列、统一间距、单次移动 ≤32 画布单位），保留明显分离的结构，不按连接重排整张图。
