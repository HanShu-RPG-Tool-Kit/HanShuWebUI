# 资源分类与共享组织规范

本文是资源类型、物理目录、虚拟文件夹和重名规则的统一说明。修改资源管理器、新建类型或工程路径前，与[多人协作编程指南](#collaboration-programming)一起阅读。

## 四层概念

| 概念 | 职责 | 定义位置 |
| --- | --- | --- |
| 资源类型 | 文件格式、扩展名、约定保存目录 | `src/resourceTypes.ts` 的 `RESOURCE_TYPES` |
| 业务分类 | 可以包含哪些资源类型；允许哪些导入转换格式 | 同文件 `GAMEPLAY_CATEGORIES` / `AUDIOVISUAL_CATEGORIES` / `STAGEPLAY_CATEGORIES`，经 `src/project/organizationDomains.ts` 注册 |
| 物理目录 | 工程读写、服务端版本与 PAK 路径的依据 | `sourcePathOf` / `sourceRelativePath` |
| 视图项目 | 共享整理文件夹、筛选分组、内置脚本、资源库表视图、脚本启动列表、任务分类入口 | 各自有明确语义，不能据图标推断落盘行为；启动列表虚入口映射固定 `load.json`，任务分类映射固定 `catalog.json` |

分类的 `types` 是资源类型列表，允许多个。第一个类型只作为默认新建格式；已有文件的格式从自身扩展名判断，不能因分类的默认类型而改写后缀。`imports` 单独描述可转换输入，例如物品库能导入 `.itemstack`，不表示它把 `.itemstack` 当作原生 `.item` 文件保存。新建模板与具体编辑器仍在各自注册表维护。

## 路径和文件夹

普通源资源保持扁平，例如 `src/items/宝刀.item`、`src/quest/序章.quest`。脚本有真实类型目录：`src/script/<common|goal|kit|shop|actor|player>/<名字>.js`。创作资料使用 `meta/docs`、`meta/voice` 等约定目录。读取工程时校验完整路径，无法由源文件模型往返表示的嵌套路径明确报错，绝不丢掉父目录后另存到分类根。

剧本工作区只展示并新建**剧本类**源资源：`src/hanshu/`、`src/character/` 与 `meta/`（文档、配音方案与服务）。全部脚本（含通用 / 玩家 / goal / kit / shop / actor）以及任务、地图、商店、物品、礼包、演员、声誉、BOSS 血条由游戏性或视听工作区管理；剧本资源树不列出它们，新建菜单也不提供对应类型，也不显示其他工作区的文件夹。分类取自 `STAGEPLAY_CATEGORIES`；`assets/` 真实目录由临时附加件展示，见[通用资源管理器底座](#explorer-shell)。

剧本、游戏性与视听效果三个工作区里用户创建的文件夹，语义完全一致：都是**共享虚拟文件夹**，只整理归属。新建、移动、重命名和删除整理文件夹不会创建或搬动磁盘目录，源文件路径（`sourcePathOf`）不变；例如放进「汉书剧本 / 第一章」的剧本仍保存在 `src/hanshu/序章.hs`。剧本 `assets/` 下的文件夹则是真实目录，不是虚拟文件夹。脚本的内置类型分类是真实目录，跨类型移动脚本会改变工程路径与运行时类型；不得把它误解成普通整理操作。

任务的单／多进度是按正文 `format` 分组的虚拟视图，不是目录。分类根的两组显示尚未归入整理文件夹的任务；已整理任务显示在其文件夹内，避免同一资源在树中出现两个相同身份的行。物品／实体表视图、内置脚本页面也不作为源文件保存。通用／玩家分类下的「通用启动列表」「玩家启动列表」是固定虚入口，正文落在 `src/script/<common|player>/load.json`，详见[脚本资源](#script-resources)。任务分类根另有固定虚入口「任务分类」，正文落在 `src/quest/catalog.json`（`hanshu.quest-catalog`）：目录 id 自动生成、对作者透明；`title` 为本地化语义键；各目录的 `quests` 是无序去重集合，同一任务可属于多个目录。译文在 `assets/<locale>/lang_quest/catalog.lang`。

## 共享元数据

`meta/explorer.json` 保存共享组织；工程 ZIP 带上它，PAK 不包含它。文件缺省等同于空组织。

```json
{
  "version": 2,
  "folders": [
    {"key": "唯一文件夹标识", "name": "装备", "category": "items", "parentId": null}
  ],
  "placements": {"src/items/宝刀.item": "唯一文件夹标识"}
}
```

`category` 是文件夹所属业务分类，必须是已注册组织域中允许文件夹的分类：游戏性分类、剧本分类（`hanshu` / `character` / `meta`）、有原生格式的视听分类。旧工程的 `version: 1` 用 `package` 字段表示同一含义，读取兼容；组织被修改后统一写回 v2。不同工作区的文件夹共存于同一文件，各工作区只替换自己域的文件夹。

`placements` 使用规范工程相对路径，不使用客户端源文件 ID，也不修改物品／实体等运行时 ID。文件夹父链允许指向可整理的固定分类键，例如 `section:script:kit`、`section:level:templates` 和 `section:level:dynamic-nav`。固定分类定义由资源管理器与元数据校验共用；静态导航器等只读视图不能作为共享父文件夹。文档直接位于固定分类时不额外保存归属，仅用户创建的整理文件夹和其归属写入共享元数据。不接受循环、跨分类父链、同级重名、缺失父级或与脚本真实类型矛盾的归属。暂未保存的文件可以先登记归属；其他客户端在源文件提交前只会看到空文件夹。

客户端编辑组织时只替换本窗口已投影的源路径，保留其他窗口尚未保存或本窗口尚未加载的归属；明确删除文件夹时才清除该文件夹剩余归属。远端刷新先读取不推进本地基线的版本快照，确认本地组织仍未修改后，一起采纳组织正文与版本。放弃组织冲突时也要先更新组织投影，不能只清理提交记录或刷新版本。

组织修改复用普通文件事务、短期写权、版本校验及恢复日志。真实源文件改名／删除与归属更新在同一事务提交。两个客户端同时修改组织时，以整个元数据文件做版本校验：后提交的旧版本失败并保留恢复请求，不自动拼接两个文件夹快照。只读成员能读取组织，但不能写入。折叠、选择、打开页签和拆分布局仍是个人界面状态。

旧 `hanshu.progressUi.v1` 是没有工程隔离的本机视图，不自动发布成共享事实。新个人界面状态使用 `hanshu.gameplayUi.v2`；旧缓存保留，不自动删除或跨工程套用。

## 名字和移动

- 普通文档在物理分类目录内唯一；虚拟文件夹不能让同分类的两个文件同名。
- 脚本在同类型内唯一，不同类型可以同名。
- 文件夹同分类、同父级内唯一。比较采用 Unicode NFC 和统一小写；文件及文件夹复用 `resourceNames.ts` 的非法字符、Windows 保留名和长度规则。
- 按裸文件名查找资源时，出现多个候选必须报歧义；需要精确查找时传规范工程路径。编译索引使用 `scriptsByPath`。
- 文件夹不能跨业务分类搬动；脚本文件夹跨类型移动时检查整个子树的目标重名，不能只检查文件夹名。
- 不用客户端隐藏按钮代替服务端权限、版本与路径检查。外部改目录应先满足规范；客户端不自动迁移磁盘文件。

## 商店模板

商店分类原生格式为 `.shop`，物理目录为 `src/shop/`，支持同格式导入。共享虚拟文件夹不改变模板路径。`.shop` 保存模板，不保存实例组合、参数注入或具体库存实体；见[商店模板规范](#shop-guide)。

## 视听效果

视听效果工作区分类在 `AUDIOVISUAL_CATEGORIES`，与 `GAMEPLAY_CATEGORIES` 并列。顶层顺序为用户界面、**BOSS血条**、头顶标记，其后为人类外观组件、人类动作、人类表情、过场动画、物品外观、建筑、粒子、雾、天空盒、背景音乐、音效、文本本地化、配音；各分类带专属资源树图标。「过场动画」内置二级 **即时演算**／**视频播片**，「建筑」内置 **原理图**／**装饰**（`AUDIOVISUAL_PACKAGE_SECTIONS`，现为只读占位）。目前仅 **BOSS血条** 有原生格式：`.bossbar`，物理目录 `src/bossbars/`，导出到 PAK 的 `bossbars/`。其余分类为占位，`types` / `imports` 为空，待后续接入资源类型。有原生格式的视听分类支持共享虚拟文件夹；占位分类不能建文件夹，协议校验会拒绝。不要把视听分类塞进游戏性分类表。详见[视听效果工作区](#audiovisual-workspace)。

## 新增资源类型

1. 在 `RESOURCE_TYPES` 声明扩展名、物理目录和业务分类。
2. 在对应工作区分类表（`GAMEPLAY_CATEGORIES` / `AUDIOVISUAL_CATEGORIES` / `STAGEPLAY_CATEGORIES`）的 `types` / `imports` 分别声明原生格式与转换输入。一个资源类型只能属于一个分类。
3. 接入新建 seed、编辑器和编译器；新类型需要专门内容校验时由对应解析器处理。
4. 通过 `sourcePathOf` 构建路径，禁止重新拼一套分类目录或按裸名字建立跨类型索引。
5. 若增加的是视图，明确它是否属于共享组织、是否筛选资源、是否只读，不能伪装成能落盘的新文件类型。

验证入口：`npm run test:resource-organization` 检查路径、类型、移动、命名、工程导出、刷新竞态及冲突同步；`npm run test:resource-organization:ui` 使用真实 S 和隔离浏览器上下文验证共享树、未保存文档归属、文件夹移动、重新打开与事务边界。

## 演员模板

演员分类原生格式为 `.actor`，保存于 `src/actors/<ID>.actor`，导出到 server PAK 的 `actors/<ID>.actor`。演员脚本使用 `src/script/actor/<ID>.js`。模板中的 `scripts` 仅引用 actor 类型脚本，保留顺序且不可重复；还可选引用声誉阵营、商店文件名和对话 `@inject`。改名、删除不自动改写引用，也不会级联删除脚本。详细契约见[演员模板与脚本](#actor-guide)。旧 `src/script/entity/` 不再作为演员脚本目录，需要作者显式调整目录，不自动改写旧工程。

## 声誉阵营

声誉分类原生格式为 `.rep`，保存于 `src/reputations/<ID>.rep`，导出到 server PAK 的 `reputations/<ID>.rep`。显示名与描述在 `assets/<locale>/lang_rep/<ID>.lang`（键 `name` / `description`），不写进 `.rep`。`hostile` 为单向阵营引用。详细契约见[声誉阵营](#reputation-guide)。
