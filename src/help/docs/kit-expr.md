# hanshu.kit.expr 表达式标准 V1

| 项 | 值 |
| --- | --- |
| 标识 | `hanshu.kit.expr` |
| 版本 | **1**（正式） |
| 适用 | 礼包（`.kit`）修饰器、指令插值、脚本接口 |
| 参考实现 | WebUI `src/workspaces/progress/kitExpr.ts` |

本标准规定礼包修饰器所用的数值表达式语言：语法、求值语义、内置函数，以及修饰器绑定到条目字段后的取值规则。WebUI 与后端引擎**必须**按本标准得到一致结果。

> 实现方**不得**借助 JavaScript `eval` / `Function` 或 Python `eval` 求值；必须自行解析，名字和函数一律按白名单解析。

## 1. 范围

V1 只做**纯标量计算**：每个值都是数字，求值没有副作用，也不访问游戏状态。分支、曲线等需求通过内置函数表达。需要更复杂的逻辑时，应使用礼包内联脚本，而不是扩展本语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| rawdata | 条目字段里作者填写的原值，例如物品数量 `5` |
| value | 字段最终生效的值 |
| 超参数 | 礼包 `params` 中声明的量。由作者与后端引擎约定，领取时由引擎注入；未注入时取 `default` |
| 修饰器 | 礼包 `modifiers` 中声明的**标量一元函数** `f(x)`，`x` 是 rawdata |
| 绑定 | 条目字段的 `mods` 指向一个修饰器 id，此时 value = 字段规则(f(rawdata)) |

用户视角：修饰器就是“输入原值、输出最终值”的函数；超参数是函数里可读的常量，由引擎决定。

## 3. 词法

- **空白**：空格、制表符、换行，忽略。
- **数字**：`[0-9]+(\.[0-9]+)?` 或 `\.[0-9]+`，例如 `3`、`1.5`、`.25`。不支持指数写法和数字分隔符。数字后不能紧跟字母、数字、`_` 或 `.`（例如 `2x` 是语法错误）。
- **名字**：`[A-Za-z_][A-Za-z0-9_]*`，区分大小写。
- **符号**：`+` `-` `*` `/` `(` `)` `,`。
- 其它字符一律是语法错误。

## 4. 语法

```ebnf
expr    = term , { ( "+" | "-" ) , term } ;
term    = unary , { ( "*" | "/" ) , unary } ;
unary   = "-" , unary | primary ;
primary = number
        | name , [ "(" , [ expr , { "," , expr } ] , ")" ]
        | "(" , expr , ")" ;
```

- 优先级从低到高依次是：加减、乘除、一元负号、调用和括号。二元运算全部左结合。
- 没有一元 `+`。
- 空表达式是语法错误。

## 5. 数值语义

- 所有数值均为 IEEE 754 双精度浮点。
- 求值时，任何二元运算或函数结果为 `NaN` / `±Infinity` 即为 **math** 错误。
- 除数为 `0` 是 **math** 错误。
- `-0` 视为 `0`。

## 6. 名字解析

在修饰器表达式里：

| 写法 | 解析为 |
| --- | --- |
| `x` | 输入 rawdata（保留名） |
| `name` | 超参数的当前值 |
| `fn(...)` | 内置函数（第 7 节） |
| `mod(e)` | 调用修饰器 `mod`，参数 `e` 作为它的 `x` |

超参数取值：

| 声明类型 | 在表达式中的值 |
| --- | --- |
| `float` | 原值 |
| `int` | 向零截断后的整数 |
| `bool` | `true` → `1`，`false` → `0` |
| `string` | 不可参与运算，引用即为 **type** 错误 |

如果注入的值无法按声明类型解释，就回落到 `default`。

**保留名**：`x` 与所有内置函数名。超参数和修饰器的 id 不得使用保留名，也不得互相重名，并且必须是合法名字。违反以上规则的声明会被拒绝，并报告声明错误。id 为空的超参数或修饰器会被**无视**，既不报错，也不可引用。

以下情况都是 **name** 错误：引用未声明的名字；把函数名当值使用（不加括号）；把超参数当函数调用。

## 7. 内置函数

参数个数不符即为 **arity** 错误。

### 7.1 算术与取整

| 函数 | 定义 |
| --- | --- |
| `min(a, …)` | 最小值；至少 1 个参数 |
| `max(a, …)` | 最大值；至少 1 个参数 |
| `abs(v)` | 绝对值 |
| `floor(v)` | 向下取整 |
| `ceil(v)` | 向上取整 |
| `round(v)` | 四舍五入，`.5` **远离 0**：`round(2.5)=3`，`round(-2.5)=-3` |
| `clamp(v, lo, hi)` | 限制在 `[lo, hi]`；若 `lo > hi` 先交换 |

> `round` 不是银行家舍入。Python 实现不能直接使用内置 `round`，应写成 `sign(v) * floor(abs(v) + 0.5)`。

### 7.2 分段

V1 不提供三元、逻辑运算和比较运算，门槛分支统一用下面两个函数。

| 函数 | 定义 |
| --- | --- |
| `step(v, edge, a, b)` | `v < edge` 时取 `a`，否则取 `b` |
| `select(v, e1, v1, …, eN, vN, vDefault)` | 依次比较：`v < e1` → `v1`；否则 `v < e2` → `v2`；……；都不满足取 `vDefault` |

`select` 的参数个数为偶数且至少 4 个；门槛 `e1 … eN` 必须严格递增，否则是 **domain** 错误。

### 7.3 曲线

| 函数 | 定义 |
| --- | --- |
| `lerp(v, at1, v1, at2, v2, …)` | 分段线性插值（折线） |
| `spline(v, at1, v1, at2, v2, …)` | Catmull-Rom 样条，曲线经过每个控制点 |

- 至少 2 个控制点，因此参数个数为奇数且至少 5 个。
- `at` 必须严格递增，否则是 **domain** 错误。
- 定义域外**钳制到端点值**：`v ≤ at1` 取 `v1`，`v ≥ atN` 取 `vN`。

`spline` 在区间 `[at_i, at_{i+1}]` 上的计算方法如下：

1. 令 `t = (v - at_i) / (at_{i+1} - at_i)`。
2. 令 `p1 = v_i`、`p2 = v_{i+1}`。
3. `p0` 取前一个控制点的值；若不存在，则 `p0 = p1`。
4. `p3` 取后一个控制点的值；若不存在，则 `p3 = p2`。
5. 按均匀 Catmull-Rom 公式求值：

```text
0.5 * ( 2·p1
      + (−p0 + p2)·t
      + (2·p0 − 5·p1 + 4·p2 − p3)·t²
      + (−p0 + 3·p1 − 3·p2 + p3)·t³ )
```

## 8. 修饰器

```json
{ "id": "loot", "label": "掉落倍率", "expr": "round(x * intensity)" }
```

- 修饰器是一元函数：`expr` 中的 `x` 绑定为调用时传入的值。
- 修饰器可以调用其它修饰器，例如 `clamp(loot(x), 1, 64)`。
- 修饰器间的调用关系构成有向图。处在环上的修饰器（含自调用）全部报 **cycle** 错误；不在环上的修饰器不受影响。
- 调用一个有错误的修饰器时，错误向上传播。
- 实现应限制调用深度，参考实现为 64 层。

## 9. 条目绑定

条目用 `mods` 把数值字段绑定到修饰器 id：

```json
{ "id": "minecraft:apple", "count": 5, "mods": { "count": "loot" } }
```

value 按以下步骤计算：

1. 未绑定：value = 字段规则(rawdata)。
2. 绑定的 id 不存在或被无视：给出**警告**，按恒等函数处理。
3. 绑定有效：value = 字段规则(f(rawdata))。
4. 求值失败：给出**错误**，value 退回字段规则(rawdata)。

字段规则：所有可绑定字段都是整数字段，先 `round`（同 7.1），再按下限钳制。

| 位置 | 字段 | 修饰器输入 | 下限 |
| --- | --- | --- | --- |
| 物品 | `count` | 数量 | 0 |
| 药水效果 | `amplifier` | **等级**，即 `amplifier + 1` | 等级 1 |
| 药水效果 | `duration` | 秒；`0` 表示无限，不经修饰器 | 0 |
| 经验 | `amount` | 点数或等级 | 0 |
| 随机池 | `rolls` | 抽取次数 | 1 |
| 随机池分组 | `weight` | 权重 | 0 |

药水等级绑定的结果是等级，写回时减 1 得到 `amplifier`。

## 10. 独立表达式

除修饰器体外，指令插值和脚本也会求值不含输入的**独立表达式**。它的语法和语义与修饰器表达式相同，只有一点不同：**不能引用 `x`**，引用即为 **name** 错误。独立表达式可以读取超参数，也可以调用修饰器，例如 `round(loot(5))`。

## 11. 指令插值

指令文本中的 `${表达式}` 按独立表达式求值，再替换为结果：

```text
give @s minecraft:apple ${round(loot(5))}
xp add @s ${loot(10)} points
```

- `${` 之后到第一个 `}` 之间为表达式；不支持嵌套花括号。
- `$${` 输出字面量 `${`，不求值。
- 结果格式：整数原样输出；否则保留最多 6 位小数，并去掉末尾的 `0`。例如 `1.5`、`0.333333`。需要整数时请显式使用 `round` / `floor`。
- 缺少 `}` 或求值失败时报告错误，该段原样保留。引擎**不应**执行含错误的指令。

## 12. 脚本接口

礼包内联脚本（Python）由引擎执行。引擎在脚本全局注入只读对象 `kit`：

| 接口 | 含义 |
| --- | --- |
| `kit.param(id)` | 超参数当前值，按声明类型返回 `float` / `int` / `bool` / `str` |
| `kit.mod(id, x)` | 对数值 `x` 应用修饰器 `id`，返回 `float`；不做字段取整 |
| `kit.expr(src)` | 求值独立表达式（第 10 节），返回 `float` |

```python
bonus = kit.mod("loot", 3)
if kit.param("hard"):
    player.give("minecraft:diamond", round(bonus))
```

以上接口出错时抛出异常，异常信息应包含第 13 节的错误类别。脚本里的数值逻辑仍应尽量写成修饰器，这样 WebUI 可以预览并检查。

## 13. 错误分类

| 类别 | 何时 |
| --- | --- |
| `syntax` | 词法或语法不合法 |
| `name` | 未知名字、未知函数、调用方式不对 |
| `type` | 引用了 `string` 超参数 |
| `arity` | 函数参数个数不符 |
| `domain` | 门槛或控制点不严格递增 |
| `math` | 除零、非有限结果 |
| `cycle` | 修饰器调用成环或过深 |

错误应尽量带上 1 起的列号，参考实现的格式为 `第 N 列：…`。

## 15. 版本与兼容

- 本文件是 V1 的完整定义。V1 **不包含**：三元 `?:`、逻辑运算 `&&` `||` `!`、比较 `<` `>` `==`、字符串和布尔值、属性访问、下标、赋值、自定义函数、指数写法。
- 后续版本只做**增量扩展**：V1 中合法的表达式在后续版本里结果不变；V1 中报错的表达式，后续版本可以赋予含义。
- 早期草案中的“采样表修饰器”不属于 V1。等价写法是 `lerp(intensity, at1, v1, …)` 乘以 `x`，或直接改用 `spline`。
