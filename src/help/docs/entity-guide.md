# 实体库：模板、快照与在线预览

在进度流程的资源管理器「实体库」中新建或导入 `.entity`。工程路径 `src/entities/<名称>.entity`；文件名是扁平模板 ID，视图文件夹只用于整理。保存仍使用工程服务的文件事务、版本检查和协作草稿，不会让浏览器直接改工程目录。

## 编辑

左侧展示在线画面或本机快照，右侧编辑实体类型、标签、外观/行为、基础属性、内嵌装备及完整 TNBT JSON 数据。最大生命、基础攻击力和移动速度为空时沿用实体默认值。名称卡片编辑普通文本；复杂名称文本可在完整数据树中编辑，读取不会自动覆盖它。

装备保存内嵌原版物品数据，不提供 `.it` 引用，包含 `rpgtoolkit:item_template` 绑定的数据会被拒绝。未由常用卡片覆盖的字段由完整数据树保留。实体库不进行模板同步，不扫描已有实体。

「捕获游戏中指向的实体」请求 MC 从服务端读取完整实体 NBT，需要原版管理员查询权限。默认剔除身份、位置、运动等状态，并解除装备模板绑定。过滤只在捕获时执行，开发接口保留自定义策略，第一版没有用户配置入口。不支持玩家和乘客/坐骑组合。捕获期间文档被修改或关闭时，不用迟到结果覆盖当前草稿。

## 在线预览与快照

连接 [游戏开发服务器](#game-dev-server) 并进入世界后，点击「开启在线预览」。MC 把实体渲染到独立离屏颜色／深度目标，再将画面串流到 WebUI，左键拖动旋转、右键平移、滚轮缩放。可选择 idle/walk/run/attack/spin 动画；「刷新预览」应用当前草稿，「重置视图」恢复朝向、平移和缩放。预览使用独立客户端实体，不在游戏世界生成实体。

加载模板时优先读取实体渲染器的 AABB，按其包围球确定一次固定比例和模型中心。旋转、俯仰和动画不会重新缩放；刷新模板后重新确定大小。渲染器未正确申报模型范围时仍可能超出边界，允许手动缩放。部分实体不具备对应动画，复杂模组实体需实机检查。

预览与已有游戏串流互斥。预览不隐藏、缩小或切换 MC 窗口，不修改游戏画面、FOV 和暂停选项。实体预览由后台线程编码 JPEG，浏览器异步解码；不额外限制发送帧率（服务状态 fps=0），按 MC 渲染节奏捕获；实际受游戏帧率设置、GPU 回读／编码／网络开销限制；手动最小化游戏仍会受到原版降帧限制。操作按带递增序号的累计量发送，不逐条等待往返；浏览器每个刷新周期只绘制最新帧。切换文件/工作区或断开游戏连接会关闭预览，无保活 15 秒也会回收。不自动抢占另一窗口的预览。

预览开始后自动将稳定帧缓存为 PNG。快照按实体数据指纹存客户端 IndexedDB，最多 200 项，不写入 `.entity`、工程资产或 PAK；离线仍可浏览本机已有快照。编辑后提示快照待更新，重新预览即可刷新。快照是当前 MC 模组和资源包环境的展示结果，不是实体配置。

## 游戏内编辑与复制魔杖

`.entity` 编辑器左侧的「发送到游戏内编辑」会用当前草稿创建 IBE 实体副本；点击 IBE 完成后结果返回 WebUI 草稿，需要保存工程。不会修改世界里的实体。若期间本机实体数据已改变，原草稿保持不动，游戏结果另存为「原名-游戏编辑结果.entity」草稿；切换工程后不会写入另一个工程。关闭 IBE 而未完成不会应用。

复制魔杖位于 NPC 魔杖所在的 **RPG ToolKit 创造标签页**，也可通过 `/rt entity wand` 获取。需要管理员权限：

- 右键实体：弹出服务端铁砧菜单填写文件名，确认后发送到当前接收的 WebUI 工程。新文件通过 S 事务保存到 `src/entities/`。
- 同名文件：WebUI 询问是否确定覆盖；有未保存修改时额外提示，取消后原文件保留。确认期间远端版本变化会提交失败，保留待处理草稿和事务记录，不强制覆盖。
- 右键方块：打开服务器实体库箱子菜单，选择后在点击面外侧生成；翻页和搜索保留该位置。列表来自已经发布／加载的 PAK，不是未发布的 WebUI 草稿。

等效指令：`/rt entity capture <目标实体> [文件名]`（省略名称则用铁砧）、`/rt entity at <x y z>`（在指定位置打开实体库）。`/rt entity spawn <模板>` 仍直接在命令位置生成。

复制数据先由游戏服务器捕获，再仅发送给操作玩家的客户端，由该客户端桥接到 WebUI。多个 WebUI 窗口连接时，最近聚焦的可写工程窗口取得接收目标；后台保活不抢占其他窗口。导入请求携带接收标识和请求编号，非目标窗口不响应，同一请求重传不会重复询问／提交。没有可写工程或连接失败时，游戏中提示未保存，不宣称成功。魔杖捕获过滤通过 `EntityTools.captureFilter` 配置，不暴露给用户。

## 网格表视图

资源树「实体库 / 实体库表视图」打开只读网格总览，可搜索文件名、实体类型和标签，点击卡片打开编辑器。默认每页 12 项，可改成 24 或 48；采用上一页／下一页离散翻页，只挂载本页卡片和读取其快照。网格使用已有本机快照，不为每张卡片开启实时串流；没有快照时显示占位，打开实体在线预览后生成。快照更新会通知已打开的网格，无需重开。表视图是虚拟文档，不保存、导出或占用文件写权。

## 注册常用字段卡片

入口 `src/workspaces/progress/entityFields/registry.ts` 的 `registerEntityFieldEditor`。内置外观／行为、属性和装备也走同一注册接口。定义唯一命名空间 `id`、`title`、`tone`、`order`、所管理的根 NBT `fields` 和 React `Editor`；`appliesTo(document)` 可限制实体类型或支持的数据形状。返回值用于注销，注册／注销后已打开的界面即时更新。

编辑器收到只读 `data`、`entityType`、`disabled` 和 `onChange(nextData)`，必须用不可变更新并遵循只读状态。宿主只采纳该卡声明的字段，其他字段始终从原数据保留；省略已声明字段表示删除它。禁止重复 ID 或重叠的根字段归属，同一复合字段的多个编辑入口应合并为一张卡。完整 TNBT 树仍是通用兜底，不受卡片覆盖范围限制。

```tsx
registerEntityFieldEditor({
  id: 'my_mod:temper', title: '性情', tone: 'violet', fields: ['Temper'],
  appliesTo: doc => doc.entity.id === 'minecraft:horse',
  Editor: TemperEditor,
})
```

## 导出与游戏端

导出到服务端 PAK 的 `entities/<名称>.entity`，继续使用 TNBT JSON，不转成无类型 JSON。Mod 通过 `EntityTemplates` 查询模板和标签、生成新实体；标准入口 `/rt entity` 提供可搜索、翻页的服务端箱子菜单，点击生成；`/rt entity spawn <模板>` 在指令位置生成。

每次生成创建新 UUID，并使用调用方指定的位置，不建立模板更新绑定。实例通过 NeoForge Data Attachment 保存创建来源：模板 ID 和自动计算的内容指纹版本（不是文件格式 version:1）；存档读取后仍保留。模板改动只影响后续生成，旧实例的来源版本保持不变。复制回模板会剥离该来源标记，重新召唤时按新模板标记。游戏端提供来源／版本／归属及当前模板标签的查询 API；模板删除后来源仍在，但标签查询不再匹配。游戏端代码与指令需要更新后的 Mod。

## 开发验证

`test:entity`：模型、目录、导出平面、帧校验与注册卡片字段保护；`test:entity:ui`：模拟 MC 传输下的 RPSF 绘制、输入、快照、捕获、关闭、只读、动态扩展卡片与网格分页；`test:entity-project:ui`：真实工程服务中的新建、保存、重开和权限。`test:entity-workbench:ui` 使用模拟 MC 传输和真实 S，验证复制、覆盖确认／取消、重复请求、IBE 草稿回传、冲突和多窗口定向接收。Mod 提供实体生成及魔杖注册 GameTest 和取景数学 JUnit。浏览器模拟帧与服务端 GameTest 不代表原生 MC 图形客户端渲染已经验收。
