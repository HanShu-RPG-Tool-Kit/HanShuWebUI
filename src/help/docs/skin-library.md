# 皮肤库

皮肤库与剧本、进度共用同一个服务端工程。C 负责预览、表单和导入准备，皮肤集合与对象文件的持久化统一经过 Rust S，受主体权限、文件写权和版本校验保护。详见[工程服务与多人协作](#collaboration-service)。

## 工程内布局

```
工程根/
  project.json
  src/
  assets/
  .hanshu/skinmanager/          # 皮肤库
    library.json                # schema v5（条目 tags 为自由字符串）
    objects/<ab>/<skinId>.skin
    cache/png/<skinId>.png
    tmp/                        # 旧工程可能保留历史准备记录；当前 C 不再读写
```

对象文件为二进制 `.skin`（像素 + 半透明 flag，不含 model）。分享串：`hanshu-skin:1:<model>:<payload>`。

实现入口：`src/skin/api/SkinApi.ts`、`src/skin/api/projectAdapter.ts`、`src/project/serviceClient.ts`。旧 Tauri 库写入适配器已删除。

## 使用

1. Chrome / Edge 打开开发页，或运行桌面壳。
2. 「文件 → 打开工程…」选择本机工程；远端使用工程分享链接或「连接其他服务器…」，以用户名和密码登录，详见[连接与协作](#collaboration-guide)
3. 切到**皮肤**工作区：导入本地 PNG（正方形 N×N 或半高 N×N/2，N∈[64…1024]）、管理文件夹；标签写在皮肤上，系统自动收集。
4. 未打开工程时皮肤页会提示先打开工程。

联网导入（玩家名 / URL）：

- **浏览器（`npm run dev`）**：玩家名经 Vite 同源代理访问 Mojang；PNG URL 直接 `fetch`（需目标站允许 CORS）。
- **桌面壳**：走 Tauri IPC → `skin-core` 的 `safe_fetch` / 玩家解析（无 CORS 限制）。

## 多人编辑与恢复

顶部头像按固定选中的皮肤显示当前协作者；悬停只是预览。查看、编辑意图、临时写权和保存状态分别显示，编辑意图不会申请写权。只读主体可以预览和导出，编辑控件禁用。新建、移动、批量标签与导入失败可在原弹窗查询或重试原提交，全局记录仍可用于统一恢复。

单条皮肤在确认字段修改时申请短期写权，由 S 校验条目版本；两个人修改不同皮肤可以分别保存。同一皮肤被别人更新后，旧修改会被拒绝，详情面板保留本地输入并提供明确的冲突处理。

导入、文件夹、全库标签和批量操作也由 S 执行业务命令。C 提交“移动这些皮肤”“重命名这个文件夹”等操作和读取时的条目版本或文件夹快照，S 在最新库上校验后落盘。不同条目的无关修改不再造成整库版本冲突；操作涉及的条目、文件夹或范围变化时，整批拒绝。文件夹的“删除”仅删除空文件夹；“清空皮肤”删除已确认子树范围内的条目，保留文件夹结构。

批量选择保留勾选时的版本。远端更新不会悄悄把选择升级为对新内容的修改授权。批量启用、禁用、标签修改和移动各自作为一个操作提交，最多 4096 条，整批成功或失败。导入队列按条目提交，允许部分条目成功。

详情输入会保存在当前窗口，切换条目或刷新后可以恢复。远端刷新和早先提交的回执不会覆盖尚未确认的新输入。写权申请失败可以重试原提交；结果未知时先查询提交结果。只有明确选择保留修改后重新提交，才会使用新的条目版本。草稿恢复不是自动提交，关闭窗口或清除站点数据可能丢失尚未提交的表单草稿。

新建、重命名和移动失败时保留当前弹窗及输入。管理操作发生版本或范围冲突后，在顶部提交记录中放弃原操作并刷新，再重新确认对象；不会把业务请求送入整个 `library.json` 的全文覆盖流程。结果未知的操作不能直接放弃，应查询结果或重试原提交。

导入失败保留首次提交的名称、位置和资料。“重试原导入”沿用原参数和条目身份；成功后丢失响应时，查询回执或重放同一请求能恢复当时的准确结果，不会再创建一条皮肤。导入队列尚未提交的文件选择和参数仍属于弹窗状态，关闭弹窗不会将它们自动变成可恢复事务；已提交的原请求按工程事务日志保存。

导入准备结果与来源保留在当前窗口内存中，不再写共享的 `tmp/import-jobs.json`，两端同时校验文件不会争抢这份队列。远端索引更新后，仍开着的导入队列可以继续保存。最近 50 条准备结果还尝试写入本窗口 sessionStorage，但不代表完整刷新后会还原整个导入弹窗；已提交操作仍以工程事务日志为恢复依据。

预览生成留在客户端，不因查看皮肤而向共享工程写入 PNG 缓存。

## 与 Rust skin-core

- `src-tauri/crates/skin-core` 供可选 Tauri IPC、联网拉取与黄金 fixtures。
- 独立进程 `skin-http` 已移除。
- Codec 对拍：`npm run test:skin-codec`。
- 皮肤管理的 HTTP 与双浏览器验收：`npm run verify:skin-management`。
- 范围快照与语义冲突边界回归：`npm run test:skin-operation-ui`。

## 旧数据

早期桌面版可能把库写在 `app_local_data_dir()/skin-manager/`。当前仅接受 schema 5，不自动转换旧版或修复索引。旧库应先完成格式转换，再将索引和对应对象文件导入当前工程的 `.hanshu/skinmanager/`；直接拷入旧格式不会自动升级。
